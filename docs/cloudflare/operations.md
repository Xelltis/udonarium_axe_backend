# 運用と料金（Cloudflare版）

部屋のサーバーを置いたあとの運用と、料金の目安をまとめました。

## キャッシュ

部屋のアセットのGETの応答には`Cache-Control: private, max-age=604800, immutable`を付けます。
部屋が消えるまで中身は変わらないので、ブラウザには7日置かせます。
ただし、トークンを持たない人に返らないよう、共有のキャッシュには置かせません。

Workerが作った応答は、CloudflareのCDNには自動では残りません。
そこでCloudflare版は、GETの応答を**Cache API**に入れ、同じデータセンターからの2回目以降はそこから返します。
キャッシュから返すときも、先に部屋のアセットのトークンを確かめます。
同じ卓の参加者は同じデータセンターにつながりやすいので、R2を読むのは実質1人分で済みます。

::: warning `*.workers.dev`ではキャッシュが効きません
Cache APIは、`*.workers.dev`のURLでは何もしません。
本番では、Workerにカスタムドメインを付けてください（→ [デプロイする](/cloudflare/deploy#_12-カスタムドメインを付ける)）。
:::

## 部屋のアセットを消すときと掃除

部屋のアセット（画像と音声）は、R2の`rooms/<部屋の鍵>/`の下に置き、部屋と一緒に消します。
部屋のGMが部屋を削除したときと、最後の1人が抜けて`ROOM_RETENTION_HOURS`（既定24時間）が過ぎて部屋を消すときに、その部屋のアセットをすべて消します。
置いてからの日数では消さないので、部屋が続いているあいだは消えません。

R2から消したあとも、データセンターのキャッシュには写しが最長7日残ります。
ただし、キャッシュから返すときも先に部屋のアセットのトークンを確かめ、部屋が消えれば新しいトークンは出ないので、写しを読めるのは消してから最長15分です。

途中で落ちたときなどに消しそこねたものは、新しく置くついでに少しずつバケットから消します。

- 新しく置いたときの約20回に1回、バケットのランダムな位置から1000件を見て、部屋の一覧に無い部屋のアセットを消します。部屋を作るのと置くのが前後しても消さないよう、置いてから1時間たったものだけを消します。
- 部屋の鍵は乱数なので、アセットはバケットの中に均等に散らばっています。ランダムな位置から見ていけば、どこまで見たかを覚えておかなくても、いずれ全体を見て回れます。
- 部屋ごとに分ける前に置いた、どの部屋にも属さない古いアセット（名前がSHA-256だけのもの）も、同じついでに消します。
- バケットはアップロードでしか増えないので、アップロードに合わせて掃除すれば、消しそこねたものがたまり続けることはありません。

R2のライフサイクル規則は要りません。
作ると、続いている部屋のアセットも日数で消えてしまいます。

## 部屋の保持

部屋のサーバーは、卓の状態を部屋ごとのDurable Object（SQLite）に置きます。

- 最後の1人が抜けてから`ROOM_RETENTION_HOURS`（既定24時間）が過ぎると、部屋を一覧から外し、置いたものと部屋のアセットをすべて消します。その前に誰かが入れば、消す予定は取り消します。
- 人がいるあいだは、1時間ごとに実際につながっている人を数え直します。Workerが落ちて全員の接続が切れても、一覧の人数を直し、そこから保持期間を数えて消します。
- 作ったまま誰も入らなかった部屋も、同じ時間で消えます。
- 卓の状態の書き込みは、オブジェクトごとに1秒ぶんまとめてから書きます。書く行の数を抑えるためです。

## 料金の目安

料金は2026年10月時点のものです。
R2は、取り出すときの転送料（egress）がかかりません。

### 単価

| 項目                     | 単価                                                                                     | 毎月の無料枠 |
| ------------------------ | ---------------------------------------------------------------------------------------- | ------------ |
| R2の保存                 | $0.015 / GB・月                                                                          | 10 GB        |
| R2のClass A（PUT・一覧） | $4.50 / 100万回                                                                          | 100万回      |
| R2のClass B（GET・HEAD） | $0.36 / 100万回                                                                          | 1000万回     |
| R2の削除                 | 無料                                                                                     | —            |
| Workersのリクエスト      | 無料プランは1日10万回まで。有料プラン（月$5）は月1000万回込み、超えた分は$0.30 / 100万回 | —            |

Workersは、キャッシュから返したリクエストも1回と数えます。

### Axeでの見込み

GMと参加者4人が、画像150枚（平均250KB）とBGM・効果音を使い、1回4時間ほど遊ぶ場合の見込みです。

画像と音声は部屋と一緒に消えるので、卓のたびに部屋を作れば、そのたびに上げ直します。
保存量は、そのとき残っている部屋の分だけです（部屋は最後の1人が抜けてから既定24時間で消えるので、1卓あたり1日ほど残ります）。
そのかわり、上げ直すぶんR2の書き込み（Class A）が増えます。

| 規模（月のセッション数）  | 保存量  | R2の月額 | Workers                          |
| ------------------------- | ------- | -------- | -------------------------------- |
| 身内（10）                | 約0.1GB | $0       | 無料プランで足りる               |
| コミュニティ（500）       | 約4GB   | $0       | 無料プランで足りる（1日約2万回） |
| 公開インスタンス（3,000） | 約24GB  | 約$0.2   | 有料プランが要る（1日約12万回）  |
| 大規模（30,000）          | 約240GB | 約$26    | 有料プランが要る（約$13）        |

最初に上限に当たるのは、**Workersの無料プランの1日10万リクエスト**です。
1セッションで約1,200回（HEAD・PUT・GET）呼ばれるので、1日に約80セッションを超えると有料プランが要ります。
大規模になると、R2の月額のほとんどは書き込み（月600万回ほど）です。

### 部屋のサーバー（Durable Objects）

| 項目                   | 無料プラン（1日あたり） | 有料プラン（月$5に込み） |
| ---------------------- | ----------------------- | ------------------------ |
| リクエスト             | 10万                    | 100万                    |
| 動いていた時間（GB-s） | 13,000                  | 40万                     |
| SQLiteに書く行         | 10万                    | 5000万                   |

- WebSocketで受けたメッセージは、20件で1リクエストと数えます。
- 部屋のサーバーは、やりとりが10秒ほど途切れると眠り（Hibernation）、その間は動いていた時間に数えません。遊んでいるあいだは、カーソルの動きなどでずっと起きています。
- 6人で4時間遊ぶと、動いていた時間が約1,800GB-s、リクエストが約1.3万、書く行が1〜2万の見込みです。
- 無料プランでは、1日に5〜7卓ほどが目安です。有料プランでは、月に約220卓が込みの範囲に入り、超えた分は1卓あたり約0.05ドルです。

これらは見積もりで、実際の卓で測った値に置き換える予定です（→ [今後の計画](/guide/roadmap)）。

## 見ておくところ

- **Workersのダッシュボード**：リクエスト数、エラーの割合、CPU時間。`observability`を有効にしてあるので、ログもダッシュボードで見られます。
- **R2のダッシュボード**：バケットの大きさと、Class A・Class Bの操作数。
- **Durable Objectsのダッシュボード**：リクエスト数、動いていた時間（GB-s）、SQLiteの読み書きした行と大きさ。
- **部屋の記録（Workers Analytics Engine）**：下の「部屋の記録」を見てください。
- **Cloudflareの請求の通知**：思わぬ使われかたに早く気づけるよう、請求額の通知を設定しておくと安心です。

## 部屋の記録

部屋のサーバーは、次のことをWorkers Analytics Engineのデータセット`udonarium_axe_rooms`に書きます。
データセットは最初に書いたときに作られるので、用意するものはありません。
無料プランでは1日10万点まで書けます。書いた行の数は1分ごとにまとめて1点にするので、4時間の卓で書くのは300点ほどです。

| `blob2`（出来事） | `blob3`（中身）          | `double1`（量）                                                 |
| ----------------- | ------------------------ | --------------------------------------------------------------- |
| `join`            | 役割                     | 部屋にいる人数                                                  |
| `leave`           | 役割                     | つないでいた秒数                                                |
| `refuse`          | 接続を閉じた理由         | 1                                                               |
| `flush`           | （空）                   | 1分のあいだにSQLiteが書いた行の数（部屋が空になったときも書く） |
| `roll`            | ゲームシステム           | 振るのにかかったミリ秒                                          |
| `delete`          | `gm`（削除した人の役割） | 削除したときに部屋にいた人数                                    |

`index1`は部屋の鍵、`blob1`はWorkerのホスト名です。
同じアカウントのWorkerは同じデータセットに書くので、`blob1`で分けて見ます。
部屋を消しても、この記録は消えません。

`flush`の数は、書いたオブジェクトの数ではなく、SQLiteが書いた行の数です。
主キーの索引の行、大きなオブジェクトを分けて置いた行（chunks）、消した印（tombstone）の行も数えるので、1つのオブジェクトでふつう2行になります。
Durable Objectsの無料プランの「SQLiteに書く行（1日10万）」と、そのまま比べられます。

SQL APIで読むには、`Account Analytics Read`の権限を付けたAPIトークンを使います。

```sh
curl "https://api.cloudflare.com/client/v4/accounts/<アカウントID>/analytics_engine/sql" \
  -H "Authorization: Bearer <APIトークン>" \
  --data "SELECT blob2 AS event, blob3 AS detail, count() AS n FROM udonarium_axe_rooms
          WHERE blob1 = 'backend.example.com' AND timestamp > NOW() - INTERVAL '1' DAY
          GROUP BY event, detail ORDER BY n DESC"
```
