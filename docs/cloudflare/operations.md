# 運用と料金（Cloudflare版）

アセットサーバーと部屋のサーバーを置いたあとの運用と、料金の目安をまとめました。

## キャッシュ

GETの応答には`Cache-Control: public, max-age=<秒>, immutable`を付けます。
`<秒>`は、7日か、保持期間の残りの短いほうです。
こうしておくと、キャッシュに残った版が、バケットから消えたあとまで「ある」と答え続けることがありません。

Workerが作った応答は、CloudflareのCDNには自動では残りません。
そこでCloudflare版は、GETの応答を**Cache API**に入れ、同じデータセンターからの2回目以降はそこから返します。
同じ卓の参加者は同じデータセンターにつながりやすいので、R2を読むのは実質1人分で済みます。

::: warning `*.workers.dev`ではキャッシュが効きません
Cache APIは、`*.workers.dev`のURLでは何もしません。
本番では、Workerにカスタムドメインを付けてください（→ [デプロイする](/cloudflare/deploy#_3-カスタムドメインを付ける)）。
:::

## 保持期間と掃除

置いてから`ASSET_RETENTION_DAYS`（既定30日）を過ぎたものは、`404`を返します。
アップロードした人が次に部屋を読み込むと、Axeが置かれているかを確かめて`404`を受け取り、上げ直します。
上げ直したものは、そこから保持期間を数え直します。

期限を過ぎたものは、新しく置くついでに少しずつバケットから消します。

- 新しく置いたときの約20回に1回、バケットのランダムな位置から1000件を見て、期限を過ぎたものを消します。
- 名前は中身のSHA-256なので、バケットの中に均等に散らばっています。ランダムな位置から見ていけば、どこまで見たかを覚えておかなくても、いずれ全体を見て回れます。
- バケットはアップロードでしか増えないので、アップロードに合わせて掃除すれば、増え続けることはありません。

R2のライフサイクル規則を作る必要はありません。
作っても構いませんが、その日数は`ASSET_RETENTION_DAYS`より短くしないでください。

## 部屋の保持

部屋のサーバーは、卓の状態を部屋ごとのDurable Object（SQLite）に置きます。

- 最後の1人が抜けてから`ROOM_RETENTION_HOURS`（既定24時間）が過ぎると、部屋を一覧から外し、置いたものをすべて消します。その前に誰かが入れば、消す予定は取り消します。
- 人がいるあいだは、1時間ごとに実際につながっている人を数え直します。Workerが落ちて全員の接続が切れても、一覧の人数を直し、そこから保持期間を数えて消します。
- 作ったまま誰も入らなかった部屋も、同じ時間で消えます。
- 卓の状態の書き込みは、オブジェクトごとに1秒ぶんまとめてから書きます。書く行の数を抑えるためです。

## 料金の目安

料金は2026年10月時点のものです。
R2は、取り出すときの転送料（egress）がかかりません。

### 単価

| 項目                     | 単価                                                                                     | 毎月の無料枠 |
| ------------------------ | ---------------------------------------------------------------------------------------- | ------------ |
| R2の保存                 | $0.015 / GB・月                                                                          | 10 GB        |
| R2のClass A（PUT・一覧） | $4.50 / 100万回                                                                          | 100万回      |
| R2のClass B（GET・HEAD） | $0.36 / 100万回                                                                          | 1000万回     |
| R2の削除                 | 無料                                                                                     | —            |
| Workersのリクエスト      | 無料プランは1日10万回まで。有料プラン（月$5）は月1000万回込み、超えた分は$0.30 / 100万回 | —            |

Workersは、キャッシュから返したリクエストも1回と数えます。

### Axeでの見込み

GMと参加者4人、画像150枚（平均250KB）とBGM・効果音を使う部屋で、毎週同じ部屋で遊ぶ場合の見込みです。

| 規模（月のセッション数）  | 保存量  | R2の月額 | Workers                                |
| ------------------------- | ------- | -------- | -------------------------------------- |
| 身内（10）                | 約0.2GB | $0       | 無料プランで足りる                     |
| コミュニティ（500）       | 約6GB   | $0       | 無料プランで足りる（1日約1.4万回）     |
| 公開インスタンス（3,000） | 約36GB  | 約$0.4   | 無料プランの上限に近い（1日約8.6万回） |
| 大規模（30,000）          | 約360GB | 約$8     | 有料プランが要る（約$10）              |

いちばん先に効いてくるのは、R2ではなく**Workersの無料プランの1日10万リクエスト**です。
1セッションで約860回（HEAD、GET、PUT）呼ばれるので、1日に約110セッションを超えると有料プランが要ります。

### 部屋のサーバー（Durable Objects）

| 項目                   | 無料プラン（1日あたり） | 有料プラン（月$5に込み） |
| ---------------------- | ----------------------- | ------------------------ |
| リクエスト             | 10万                    | 100万                    |
| 動いていた時間（GB-s） | 13,000                  | 40万                     |
| SQLiteに書く行         | 10万                    | 5000万                   |

- WebSocketで受けたメッセージは、20件で1リクエストと数えます。
- 部屋のサーバーは、やりとりが10秒ほど途切れると眠り（Hibernation）、その間は動いていた時間に数えません。遊んでいるあいだは、カーソルの動きなどでずっと起きています。
- 6人で4時間遊ぶと、動いていた時間が約1,800GB-s、リクエストが約1.3万、書く行が1〜2万の見込みです。
- 無料プランでは、1日に5〜7卓ほどが目安です。有料プランでは、月に約220卓が込みの範囲に入り、超えた分は1卓あたり約0.05ドルです。

これらは見積もりで、実際の卓で測った値に置き換える予定です（→ [今後の計画](/guide/roadmap)）。

## 見ておくところ

- **Workersのダッシュボード**：リクエスト数、エラーの割合、CPU時間。`observability`を有効にしてあるので、ログもダッシュボードで見られます。
- **R2のダッシュボード**：バケットの大きさと、Class A・Class Bの操作数。
- **Durable Objectsのダッシュボード**：リクエスト数、動いていた時間（GB-s）、SQLiteの読み書きした行と大きさ。
- **部屋の記録（Workers Analytics Engine）**：下の「部屋の記録」を見てください。
- **Cloudflareの請求の通知**：思わぬ使われかたに早く気づけるよう、請求額の通知を設定しておくと安心です。

## 部屋の記録

部屋のサーバーは、次のことをWorkers Analytics Engineのデータセット`udonarium_axe_rooms`に書きます。
データセットは最初に書いたときに作られるので、用意するものはありません。
無料プランでは1日10万点まで書けます。書き込みの数は1分ごとにまとめて1点にするので、4時間の卓で書くのは300点ほどです。

| `blob2`（出来事） | `blob3`（中身）  | `double1`（量）                                           |
| ----------------- | ---------------- | --------------------------------------------------------- |
| `join`            | 役割             | 部屋にいる人数                                            |
| `leave`           | 役割             | つないでいた秒数                                          |
| `refuse`          | 接続を閉じた理由 | 1                                                         |
| `flush`           | （空）           | 1分のあいだに書いた変更の数（部屋が空になったときも書く） |
| `roll`            | ゲームシステム   | 振るのにかかったミリ秒                                    |

`index1`は部屋の鍵、`blob1`はWorkerのホスト名です。
同じアカウントのWorkerは同じデータセットに書くので、`blob1`で分けて見ます。

SQL APIで読むには、`Account Analytics Read`の権限を付けたAPIトークンを使います。

```sh
curl "https://api.cloudflare.com/client/v4/accounts/<アカウントID>/analytics_engine/sql" \
  -H "Authorization: Bearer <APIトークン>" \
  --data "SELECT blob2 AS event, blob3 AS detail, count() AS n FROM udonarium_axe_rooms
          WHERE blob1 = 'assets.example.com' AND timestamp > NOW() - INTERVAL '1' DAY
          GROUP BY event, detail ORDER BY n DESC"
```
