# 部屋のプロトコル

[部屋のサーバー](/cloudflare/rooms)とAxeのあいだでやりとりするものの形です。
型と定数は`apps/cloudflare/contracts/protocol.ts`に、例は`apps/cloudflare/contracts/fixtures/`にあります。
このページの内容と食い違うときは、そちらが正しいものです。
いまの版は**2**です。ログインのAPIは[ログインと役割](/cloudflare/login)にあります。

## HTTP

| メソッド | パス                                                 | 内容                                             |
| -------- | ---------------------------------------------------- | ------------------------------------------------ |
| `POST`   | `/v1/rooms`                                          | 部屋を作る                                       |
| `GET`    | `/v1/rooms`                                          | 部屋の一覧                                       |
| `GET`    | `/v1/rooms/:roomKey`                                 | 部屋を鍵で1つ引く                                |
| `DELETE` | `/v1/rooms/:roomKey`                                 | 部屋を削除する（その部屋のGMだけ）               |
| `GET`    | `/v1/rooms/:roomKey/ws`                              | 部屋に入る（WebSocketにつなぎ替える）            |
| `HEAD`   | `/v1/rooms/:roomKey/assets/:sha256`                  | 部屋のアセットが置かれているか                   |
| `GET`    | `/v1/rooms/:roomKey/assets/:sha256`                  | 部屋のアセットの中身                             |
| `PUT`    | `/v1/rooms/:roomKey/assets/:sha256`                  | 部屋のアセットを置く（その部屋のGMとPLだけ）     |
| `GET`    | `/v1/rooms/:roomKey/assets`                          | 部屋に置いてあるアセットの一覧                   |
| `POST`   | `/v1/rooms/:roomKey/assets/:sha256/uploads`          | 置き場所へ直接上げる先を受け取る（Vercel版だけ） |
| `POST`   | `/v1/rooms/:roomKey/assets/:sha256/uploads/complete` | 直接上げ終えたことを知らせる（Vercel版だけ）     |

どれも、`ACCESS_CONTROL_ALLOW_ORIGIN`に書いたOriginのページからしか受けません。
ほかのOriginには`403 origin-not-allowed`を返します。
`POST`・`DELETE`と、`GET`の一覧と1つの部屋、部屋のアセットは、CORSのプリフライトにも答えます。

### `POST /v1/rooms`

ログインした人だけが作れます。作った人が、その部屋のGMになります。

```http
POST /v1/rooms
Origin: https://axe.example.com
Authorization: Bearer <アクセストークン>
Content-Type: application/json

{ "name": "金曜の卓", "password": "secret" }
```

| フィールド | 型     | 内容                                     |
| ---------- | ------ | ---------------------------------------- |
| `name`     | 文字列 | 部屋の名前。1〜255文字                   |
| `password` | 文字列 | 省けば、パスワードの無い部屋。64文字まで |

`201`で次を返します。

```json
{ "roomKey": "511c18c897b08d168145a815870cf90b", "roomId": "O46" }
```

- `roomKey`：部屋の鍵。128ビットの乱数を小文字の16進で書いた32文字。部屋に入るときと、招待リンクに使います。
- `roomId`：表示用の3文字。ほかの部屋とぶつかることがあります。部屋は`roomKey`で区別します。

| 状態  | 本文                            | 起きるとき                                             |
| ----- | ------------------------------- | ------------------------------------------------------ |
| `400` | `{"error":"invalid-request"}`   | 本文がJSONでない、名前やパスワードの形が違う           |
| `401` | `{"error":"login-required"}`    | アクセストークンが無いか、無効か、期限切れ             |
| `429` | `{"error":"rate-limited"}`      | 送信元から部屋を作る・入る・削除する回数が上限を超えた |
| `503` | `{"error":"login-unavailable"}` | このWorkerにログインが置かれていない                   |

### `GET /v1/rooms`

```json
{
  "rooms": [
    {
      "roomKey": "511c18c8…",
      "roomId": "O46",
      "name": "金曜の卓",
      "hasPassword": true,
      "members": 2
    }
  ]
}
```

新しく作られた順に、1000件まで返します。
`members`はいま入っている人数です。誰もいない部屋も、消えるまでは一覧に出ます。
Workerが落ちて、出ていく知らせが無いまま接続が切れたときは、1時間以内に数え直します。

アクセストークンを付けて取ると、その人がGMの部屋に`"deletable": true`が付きます。
その部屋は、1000件に入らない古いものでも必ず返します。
トークンが無いか読めないとき、GMでない部屋には付きません。

一覧は、だれが取っても部屋の鍵を返します（→ [部屋の鍵を知っていれば入れる](/cloudflare/security#部屋の鍵を知っていれば入れる)）。
送信元ごとの読み出しの上限（`READ_LIMITER`。部屋のアセットを読むのと合わせて1分600件）を超えると、`429 rate-limited`を返します。

### `GET /v1/rooms/:roomKey`

部屋の鍵で、1つの部屋を引きます。答えは`{ "room": { … } }`で、`room`の形は一覧の1件と同じです。
一覧に入らない古い部屋も引けるので、Axeは招待リンクを開いたときと、つなぎ直すときにこれを使います。
アクセストークンを付ければ、その人がGMの部屋に`"deletable": true`が付きます。
部屋が無ければ`404 room-not-found`、鍵の形が違えば`400 invalid-id`を返します。
数え方（`READ_LIMITER`）は一覧と同じです。

### `DELETE /v1/rooms/:roomKey`

部屋を削除します。削除できるのは、その部屋のGMだけです。

```http
DELETE /v1/rooms/511c18c897b08d168145a815870cf90b
Origin: https://axe.example.com
Authorization: Bearer <アクセストークン>
```

`204`を返します。
部屋にいる人には`room-deleted`を送ってから、接続を閉じます。
そのあとは保持期間が過ぎたときと同じく、部屋を一覧から外し、置いたものと部屋のアセットをすべて消します。
消しているあいだ（一覧やR2を待つあいだ）は、新しい接続も`hello`も`room-not-found`で断り、部屋のアセットのトークンも渡し直しません。保持期間が過ぎて消すときも同じです。

| 状態  | 本文                            | 起きるとき                                             |
| ----- | ------------------------------- | ------------------------------------------------------ |
| `400` | `{"error":"invalid-id"}`        | 部屋の鍵の形が違う                                     |
| `401` | `{"error":"login-required"}`    | アクセストークンが無いか、無効か、期限切れ             |
| `403` | `{"error":"not-game-master"}`   | その部屋のGMでない                                     |
| `404` | `{"error":"room-not-found"}`    | 部屋が無い（作られていないか、消えた）                 |
| `429` | `{"error":"rate-limited"}`      | 送信元から部屋を作る・入る・削除する回数が上限を超えた |
| `503` | `{"error":"login-unavailable"}` | このWorkerにログインが置かれていない                   |

### `GET /v1/rooms/:roomKey/ws`

WebSocketにつなぎ替えます（`101`）。
つなぎ替える前に断るときは、JSONで理由を返します。

| 状態  | コード               | 起きるとき                                             |
| ----- | -------------------- | ------------------------------------------------------ |
| `400` | `invalid-id`         | 部屋の鍵の形が違う                                     |
| `403` | `origin-not-allowed` | Originが許可リストにない                               |
| `426` | `upgrade-required`   | WebSocketの要求でない                                  |
| `429` | `rate-limited`       | 送信元から部屋を作る・入る・削除する回数が上限を超えた |

部屋が無いとき（部屋を消しているあいだも）と、部屋が受けるWebSocketの数（64本）に達しているときは、つなぎ替えてから`error`（`room-not-found`・`room-full`）を送って閉じます。
HTTPのまま断ると、ブラウザには理由が読めないためです。

トークンやパスワードはURLに載せません。
パスワードは、つないだあとの`hello`で送ります。

### 部屋のアセット

その部屋の画像と音声は、`/v1/rooms/:roomKey/assets/:sha256`で読み書きします。
`HEAD`で置かれているかを確かめ、`GET`で受け取り、`PUT`で置きます。
`:sha256`は、中身のSHA-256を小文字の16進で書いた64文字です。
R2には`rooms/<部屋の鍵>/<SHA-256>`の名前で置くので、同じ中身でも部屋が違えば別に置きます。
`GET /v1/rooms/:roomKey/assets`は、その部屋に置いてあるアセットの一覧（`{ assets: [{ id, type, size, name }] }`）を返します。

```http
PUT /v1/rooms/511c18c897b08d168145a815870cf90b/assets/<sha256>
Origin: https://axe.example.com
Authorization: Bearer <アセットのトークン>
Content-Length: <大きさ>
X-Asset-Name: <ファイル名をencodeURIComponentしたもの>
```

どれにも、部屋のサーバーが席に渡したアセットのトークン（→ [部屋のアセットのトークン](#部屋のアセットのトークン)）を付けます。
ログインのアクセストークンでは通りません。
読む（`HEAD`・`GET`）のはその部屋の席ならだれでも、置く（`PUT`）のはGMとPLだけです。
`PUT`は、置いたら`201`（`{"id":"<sha256>","status":"stored"}`）を、その部屋にすでに置かれていれば`200`（`"status":"exists"`）を返します。
`PUT`に付けた`X-Asset-Name`（255文字まで）は、一覧の`name`になり、`HEAD`と`GET`の答えにも同じヘッダーで付きます。画像のカタログには名前が無いので、Axeはこれで取った画像に名前を付けます。
中身を置いているあいだに部屋が削除されたときは、置いたものを消して`404`を返します。
置くときは、部屋がまだあり、その人がいまGMかPLとして席にいるかを部屋のサーバーに尋ねます。トークンは15分使えるので、そのあいだに削除した部屋や、見学に変えられた人、抜けた人からのものを断るためです。
部屋のアセットは、部屋と一緒に消えます。

| 状態  | コード                 | 起きるとき                                                                         |
| ----- | ---------------------- | ---------------------------------------------------------------------------------- |
| `400` | `invalid-id`           | 名前が64文字の小文字16進でない、部屋の鍵の形が違う                                 |
| `401` | `asset-token-required` | トークンが無い・無効・期限切れ・ほかの部屋のもの                                   |
| `403` | `not-a-player`         | 見学のトークンで置こうとした。置くときに見学に変えられていたか、部屋から抜けていた |
| `403` | `origin-not-allowed`   | Originが許可リストにない                                                           |
| `404` | `not-found`            | その部屋に置かれていない（部屋が消えて、一緒に消えたときも）                       |
| `404` | `room-not-found`       | 置くときに部屋がもう無い（削除したか、消えた）                                     |

返すヘッダー、形式と大きさの上限、条件付きリクエストと範囲指定、ほかのコード（`411`・`413`・`415`・`429`・`451`など）は、[APIリファレンス](/cloudflare/api)にあります。

### 置き場所へ直接上げる

1回の要求の本文に上限のある部屋のサーバー（Vercel版は4.5MB）は、`welcome`の`assetUpload`でそれを知らせます。
`assetUpload`が無ければ（Cloudflare版）、種類ごとの上限（画像2MiB、音声10MiB）まで1回の`PUT`で置けます。

```json
{ "maxPutBytes": 4000000, "directUpload": true }
```

`maxPutBytes`を超えるものは、`PUT`では`413 too-large`になります。
`directUpload`が`true`なら、置き場所（Vercel Blob）へ直接上げます。

1. `POST /v1/rooms/:roomKey/assets/:sha256/uploads`に、`{"size":<大きさ>,"name":"<ファイル名>"}`を送ります。アセットのトークンを付けます。
2. `201`で`{ticket, upload:{url, method, headers, expiresAt}}`が返ります。すでに置かれていれば、`PUT`と同じ`200`（`"status":"exists"`）です。
3. `upload.url`へ、`upload.method`（`PUT`）と`upload.headers`で、中身だけを送ります。アセットのトークンは付けません。
4. `POST /v1/rooms/:roomKey/assets/:sha256/uploads/complete`に、`{"ticket":"<ticket>"}`を送ります。アセットのトークンを付けます。
5. 部屋のサーバーが中身の形式・大きさ・SHA-256を確かめ、置けたら`201`（`"status":"stored"`）を返します。

- 確かめる順とコードは`PUT`と同じです。数を絞るのは、1で尋ねたときだけです。
- `ticket`は、部屋・アセット・その人・大きさの約束で、15分で切れます。ほかの部屋やアセット、ほかの人のものは`400 invalid-request`になります。
- `upload`の先が使えるのは`expiresAt`（Unixミリ秒）までです。置き場所が、大きさと期限と上書きしないことを確かめます。
- 上げていないうちに知らせると`404 not-found`です。上げたものは、確かめたあと（置けても置けなくても）消します。
- 直接上げる流れの無い部屋のサーバーでは、どちらのパスも`404 not-found`です。

## WebSocketのフレーム

- **バイナリのフレーム**：中身は、下の封筒をMessagePackにしたものです。フレーム全体をgzipしても構いません。先頭の2バイトが`1f 8b`ならgzipとみなします。サーバーは、1KiBを超えて縮むフレームをgzipして送ります。
- **テキストのフレーム**：生きているかの確認にだけ使います。`ping`を送ると`pong`が返ります。この応答は部屋のサーバーを起こさずに返るので、こまめに送っても料金に響きません。`ping`のほかのテキストを送ると、`bad-message`で閉じます。

省けるフィールドは、無くても`null`でも構いません（MessagePackは`undefined`を`nil`にするため）。

## クライアントから送るもの

### `hello`

つないで最初に送ります。これより前に別のものを送ると、`hello-required`で切られます。

```json
{
  "type": "hello",
  "protocolVersion": 2,
  "peerId": "a1B2c3XyZq9W8e7r6-",
  "userId": "acct_8c5b7f0e-2c1d-4e3f-9a8b-7c6d5e4f3a2b",
  "password": "secret",
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.…",
  "invite": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.…"
}
```

- `peerId`は、SkyWay版と同じ形のピアIDです。英数字・`_`・`-`の64文字までに限ります。部屋にいるほかの人のピアIDは名乗れません（`bad-message`）。ただし、ログインした人のピアIDを見学が先に取っていたら、その人が入ってきたときに見学のほうを`bad-message`で外します。ピアIDはユーザーIDから作るので、ログインした人のピアIDを持てるのはその人だけだからです。
- Axeの部屋の形のピアID（ユーザーIDのダイジェスト6文字、部屋のID3文字、部屋の名前のダイジェスト8文字、`-`、パスワードがあればそのダイジェスト7文字）は、頭のダイジェストが`userId`のもの（SHA-256をbase62にした頭の6文字）でなければ`bad-message`で断ります。部屋にいない人のピアIDを取っておいて、戻ってきた本人を締め出すことはできません。ただし6文字は総当たりで合わせられるので、見学者は、自由に名乗れるユーザーIDを選んで、抜けているあいだのほかの見学者のピアIDを取れることがあります。そのあいだ、その見学者は入れません。ログインした人は、戻れば見学の側が外れます。見え方はユーザーIDで決まるので、これで見えるものは増えません。
- ログインした人が入ってくると、同じ`userId`をトークン無しで名乗っていた見学の席を`unauthorized`で閉じます。
- `password`は、パスワードのある部屋に入るときに付けます。
- `accessToken`は、ログインしているときに付けます。付けなければ見学（`guest`）として入ります。付けるなら、`userId`はアカウントの`userId`と同じにします。違うと`unauthorized`で切られます。Workerからログインを外したあとは、付けると`unauthorized`で切られ、見学としてだけ入れます。
- 付けないときは、`userId`を`acct_`で始めてはいけません（ログインした人のユーザーIDの形です）。この部屋にログインして入ったことのある`userId`（`acct_`の付かない前の形のアカウントを含む）も名乗れません。どちらも`unauthorized`で切られます。見え方はユーザーIDで決まるので、ほかの人のユーザーIDを名乗れば、その人の手札や秘話が見えてしまうためです。
- `invite`は、招待リンクに付いてきた招待です。ログインした人がその部屋に初めて入るときの役割になります。役割を覚えるのは席に着けたときだけなので、`room-full`などで断られたときは、次に入るときにもその招待が効きます。
- `hello`のすぐあとに、返事を待たずに別のものを送っても構いません。入れたあとで順に処理します。

### `send`

イベントの束を送ります。

```json
{
  "type": "send",
  "to": "Zz9Yy8XyZq9W8e7r6-",
  "events": [
    {
      "eventName": "WRITING_A_MESSAGE_DETAIL",
      "data": "…",
      "sendFrom": "a1B2c3XyZq9W8e7r6-"
    }
  ]
}
```

- `to`を省けば、自分以外の全員に届きます。`to`を付ければ、その人にだけ届きます。いない人や自分を宛先にしたものは捨てます。
- `sendFrom`は、サーバーが受けた接続のピアIDで上書きします。ほかの人になりすますことはできません。
- 送り主には返しません。自分の送ったものは、Axeが自分で折り返しています。
- 1つの束に入れられるイベントは4096までです。

### `time`

`{"type":"time"}`を送ると、サーバーの時刻を返します。時計のずれを測るのに使います。

### `invite`

`{"type":"invite","role":"pl"}`を送ると、その役割で入れる招待を返します。GMだけが作れます（→ [招待](/cloudflare/login#招待)）。

### `auth`

`{"type":"auth","accessToken":"…"}`で、つながったまま新しいアクセストークンを渡します。
ログインして入った席は、アクセストークンが切れて1分（`TOKEN_GRACE_MS`）を過ぎても新しいものが届かなければ、`unauthorized`で閉じます。
ログアウトした人やアカウントを消した人が、つながったまま見続けないためです。
そうした席を外すのは、部屋にフレームが届いたときと、部屋の見回り（alarm）のときです。
見回りは、1時間ごとと、部屋でいちばん早く切れるトークンが切れて1分1秒たったときの、早い方に置きます。そのため、だれも何も送らない部屋でも外れます。
外れて部屋が空になったら、ふつうに出ていったときと同じく、保持期間を数え始めます。
Axeは、トークンを替えたらすぐ送ります。
見学の席から送っても何もしません。
ほかの人のトークンを送ると、`unauthorized`で閉じます。

### `asset-token`

`{"type":"asset-token"}`を送ると、部屋のアセットの新しいトークンを`asset-token`で返します（→ [部屋のアセットのトークン](#部屋のアセットのトークン)）。
どの役割の席からでも頼めます。
部屋を消しているあいだは、渡し直しません。

## サーバーから送るもの

| `type`        | 中身                                                                                                                                              | 送るとき                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `welcome`     | `protocolVersion`、`peerId`、`authorityPeerId`、`role`、`members`、`serverTime`、`assetToken`、`assetTokenExpiresAt`、`assetUpload`（省略できる） | `hello`が通ったとき                                   |
| `join`        | `member`（`peerId`、`userId`、`role`）                                                                                                            | 誰かが入ったとき                                      |
| `leave`       | `peerId`                                                                                                                                          | 誰かが抜けたとき                                      |
| `data`        | `from`（送り主のピアID）、`events`                                                                                                                | イベントを届けるとき                                  |
| `time`        | `serverTime`（Unixミリ秒）                                                                                                                        | `time`を受けたとき                                    |
| `invite`      | `role`、`invite`、`expiresAt`。GMでないときと、Workerにログインが置かれていないときは`invite`と`expiresAt`が`null`                                | `invite`を受けたとき                                  |
| `asset-token` | `assetToken`、`expiresAt`（Unixミリ秒）、`role`（その席のいまの役割）                                                                             | `asset-token`を受けたときと、自分の役割が変わったとき |
| `error`       | `code`、`protocolVersion`                                                                                                                         | 接続を閉じる前                                        |

- `welcome`の`role`は、サーバーが決めた自分の役割（`gm`・`pl`・`guest`）です。自分の`PeerCursor`の`role`はこれにします。
- `welcome`の`members`には、つないだ本人とサーバーは入りません。
- サーバー自身のピアIDは`welcome`の`authorityPeerId`（`@authority`）で知らせます。ピアIDの形から推し量らないでください。
- `welcome`のすぐあとには、必ずサーバーのカタログ（`from`が`@authority`の`data`）が届きます。部屋が空でも、空のカタログが1件届きます。
- `welcome`の`assetUpload`は、アセットの置き方です（→ [置き場所へ直接上げる](#置き場所へ直接上げる)）。
- 省略できる欄は、これからも足すことがあります。知らない欄は無視してください。

### 部屋のアセットのトークン

`welcome`の`assetToken`は、この部屋のアセット（→ [部屋のアセット](#部屋のアセット)）を読み書きするトークンです。
`Authorization: Bearer`に付けて使います。
中身は部屋の鍵、その席の役割とユーザーID（`uid`）で、`SESSION_SECRET`で署名し（HS256）、15分で切れます。
切れる時刻は`assetTokenExpiresAt`（Unixミリ秒）です。

```json
{
  "type": "asset-token",
  "assetToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.…",
  "expiresAt": 1792000900000,
  "role": "pl"
}
```

- 切れる前に、Axeは`{"type":"asset-token"}`を送り、上の形で新しいトークンを受け取ります。届いたら、今のトークンと入れ替えます。
- 役割が変わったときも、サーバーはその人に新しい役割のトークンを送ります（PLをGMにしたときなど）。置けるかどうかは、トークンの役割で決まるためです。
- `asset-token`の`role`には、その席のいまの役割が入ります。Axeはこれで自分の役割を知り直します（見学からPLになったら、手元の画像や音声を部屋に上げるなど）。
- 切れる時刻の名前は、`welcome`では`assetTokenExpiresAt`、`asset-token`では`expiresAt`です。
- 部屋を抜けた人が読めるのは、持っているトークンが切れるまで（最長15分）です。
- Workerからログインの3つを外したあとは、`assetToken`は空文字に、`assetTokenExpiresAt`は`0`になり、部屋のアセットは使えません。

## サーバーが中身を読むイベント

ほかのイベントは、中身を読まずにそのまま届けます。

| イベント                  | サーバーがすること                                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `UPDATE_GAME_OBJECT`      | 版を比べ、新しければ置いて、宛先にかかわらずほかの全員に配る（→ [新しい方を勝たせる](/cloudflare/rooms#新しい方を勝たせる)）                         |
| `DELETE_GAME_OBJECT`      | 消して印を残し、宛先にかかわらずほかの全員に配る。印を残すかは、送られてきた種類名ではなく、置いてあるものの種類で決める（`PeerCursor`には残さない） |
| `FORGET_DELETED_OBJECTS`  | 消した印を外し、ほかの全員に配る。見学者からのものは受けない                                                                                         |
| `ROLE_REQUEST`            | 宛先がサーバーか、宛先なしなら、役割を変える（→ [役割を変える](/cloudflare/login#役割を変える)）                                                     |
| `ROLL_REQUEST`            | 宛先がサーバーか、宛先なしなら、ダイスを振って結果の発言を全員に配る（→ [サーバーで振るダイス](#サーバーで振るダイス)）                              |
| `SYNCHRONIZE_GAME_OBJECT` | 宛先がサーバーか、宛先なしなら、サーバーが答える。足りないものを取り寄せ、消したものは消させる                                                       |
| `REQUEST_GAME_OBJECT`     | 宛先がサーバーか、宛先なしなら、サーバーが持っているものを返す                                                                                       |
| `REQUEST_CATALOG`         | 宛先がサーバーか、宛先なしなら、サーバーのカタログを返す                                                                                             |

カタログは、1つのイベントに2048件ずつ入れます。
宛先がほかの参加者になっている`SYNCHRONIZE_GAME_OBJECT`・`REQUEST_GAME_OBJECT`・`REQUEST_CATALOG`・`ROLE_REQUEST`・`ROLL_REQUEST`は、読まずにその人へ届けます。

`PeerCursor`は、その席だけが書けて消せます。
サーバーは、`syncData`の`peerId`・`userId`・`role`を、いつもその席の値で上書きします。
送った値と違っていたら、送り主には直したものを`AUTHORITATIVE_OBJECT`で返します。
部屋にいるほかの人のピアIDを名乗る新しいカーソルは断り、部屋にいない人のピアIDのものは何も返さずに捨てます。

入り直した人（`replaced`）の古い接続のカーソルは消して、ほかの人にも`DELETE_GAME_OBJECT`を送ります。
部屋にいない人のカーソル（Workerが落ちて、出ていく知らせが来なかったもの）は、だれかが入ってきたときと1時間ごとの見回りで消し、同じく`DELETE_GAME_OBJECT`を送ります。

## サーバーが送るイベント

`from`が`@authority`の`data`で届きます。

| イベント               | 中身                                  | すること                                                                                                     |
| ---------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `AUTHORITATIVE_OBJECT` | オブジェクトの中身（`ObjectContext`） | 版にかかわらず置き換え、消した印も外す。書く権限の無い変更を戻すときと、サーバーが直したものを渡すときに使う |
| `WITHDRAW_GAME_OBJECT` | `{ identifier }`                      | 消した印を残さずに、手元から外す。書く権限の無い人が作ったものを取り下げさせるときに使う                     |
| `ROLE_REJECTED`        | `{ peerId, role, reason }`            | `ROLE_REQUEST`を断った。理由は[役割を変える](/cloudflare/login#役割を変える)にある                           |
| `ROLL_REJECTED`        | `{ identifier, reason }`              | `ROLL_REQUEST`を振らなかった。理由は[サーバーで振るダイス](#サーバーで振るダイス)にある                      |

この4つのイベントは、クライアントが送ってきても、サーバーはだれにも届けません。

## サーバーで振るダイス

チャットのダイスのコマンドは、サーバーがBCDiceで振ります。
振った人の手元で振らないので、結果を書き換えて送ることはできません。

Axeは、自分で振るときと同じ形で結果の発言（`chat`）を用意し、まだ手元には置かずに、コマンドと一緒にサーバーへ送ります。

```json
{
  "eventName": "ROLL_REQUEST",
  "data": {
    "message": {
      "aliasName": "chat",
      "identifier": "…",
      "majorVersion": 1,
      "minorVersion": 0.5,
      "syncData": { "parentIdentifier": "<タブ>", "…": "…" }
    },
    "command": "2d6+3",
    "gameSystem": "SwordWorld2.5",
    "speaker": "Kai",
    "suffix": " [ゴブリン]"
  }
}
```

| フィールド   | 内容                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| `message`    | 用意した結果の発言                                                                                          |
| `command`    | 振るコマンド。全角を半角に直したもの。先頭に回数（`3 2d6`）を付けてもよい。4000文字まで                     |
| `gameSystem` | ゲームシステムのID。知らないものなら`DiceBot`で振る                                                         |
| `speaker`    | 発言した人の名前                                                                                            |
| `suffix`     | 結果の文面の後ろに付ける対象のキャラの名前。` [名前]`の1行だけで、名前は改行と角括弧と`→`を含まず128文字まで。省いてよい |

サーバーは振った結果で、発言の次の項目を埋め、新しい発言として全員に配ります（振った人にも届きます）。
`value`は`syncData`の直下、ほかはChatMessageのSyncVarなので`syncData.attributes`に入ります。

| 項目         | 入れるもの                                                           |
| ------------ | -------------------------------------------------------------------- |
| `value`      | 結果の文面（`DiceBot : (1D6) → 4`の形。Axeが自分で振ったときと同じ） |
| `dicebot`    | 出目と成否のJSON                                                     |
| `tag`        | `system`。シークレットダイスなら`system secret`                      |
| `name`       | `<BCDice：名前>`。シークレットダイスなら`<Secret-BCDice：名前>`      |
| `from`       | `System-BCDice`                                                      |
| `originFrom` | 振った人の`userId`                                                   |
| `serverRoll` | `true`                                                               |

- 振れるのは、タブの一覧（`ChatTabList`）の直下にあるタブだけです。ほかのところに置こうとした結果は`invalid`で断ります。見えないところで振り、よい目のときだけ見えるところへ移せないようにするためです。同じ理由で、GMのほかはタブを別の親の下へ移せません。
- 見学者は、見学者も話せるタブでだけ振れます。
- 結果の時刻（`timestamp`）は、サーバーの時刻より10分以上前なら、10分前のところへ寄せます。手元の時計のずれは許しつつ、行を並びの奥へ埋めさせないためです。先の時刻は寄せません。Axeは次の発言をタブの最後の行より後ろの時刻に置くので、先の時刻の行があるタブでも、結果は頼んだ発言のすぐ後ろに並びます。
- 並びの位置は、`majorIndex`を0にし、`minorIndex`は0以上1未満のときだけ受けます（その外なら0）。Axeが発言に付けるのはこの範囲だけです。
- 頼んだ結果に付いてきた飾りと印は持ち込みません。`stamp`・`attachmentImageIdentifiers`・`replyTo`・`quoteOf`は空に、`fixd`は`false`にし、`editHistory`・`disclosedAt`・`pseudoDeletedAt`・`afterWhisperAt`・`afterWhisperTo`・`afterWhisperName`は外します。
- サーバーが振った発言は、あとから`value`、親のタブ（`parentIdentifier`）、`attributes`の`dicebot`・`tag`・`name`・`from`・`originFrom`・`serverRoll`・`to`（宛先）・`timestamp`（時刻）・`disclosedAt`（並びの時刻）・`editHistory`・`fixd`・`stamp`・`attachmentImageIdentifiers`・`replyTo`・`quoteOf`・`afterWhisperAt`・`afterWhisperTo`・`afterWhisperName`を書き換えられません。`syncData`の直下にある並びの位置（`majorIndex`・`minorIndex`）も同じです（ほかの項目は書き換えられる）。書き換えて送ってきたら、元に戻したものを`AUTHORITATIVE_OBJECT`で返します。
- ただし、振った人（`originFrom`の人）とGMは、シークレットを公開できます。`tag`から`secret`の語を外すこと（`system secret`を`system`に）と、そのときに末尾へ移すこと（`disclosedAt`と`minorIndex`。`disclosedAt`は10分以上前なら10分前へ寄せ、`minorIndex`は0以上1未満だけを受ける）だけを受け付けます。公開すると、伏せて届けていた人にも結果の全体が届きます。
- 消したことにする印（`pseudoDeletedAt`）を付けられるのはGMだけで、結果の発言そのものを消せるのもGMだけです。結果の入ったタブを消せるのもGMだけで、ほかの人が消そうとすると、その人に見えていたものを`AUTHORITATIVE_OBJECT`で返します。そのあと10秒のあいだは、同じ人がそのタブの中の行を消そうとしても消させません。Axeはタブを消すとき、続けて中の行を1つずつ消すからです。
- `serverRoll`は、サーバーが振った発言にしか付きません。クライアントが付けて送ってきても外します。Axeはこれを見て、サーバーで振った結果だとわかるように見せられます。
- ダイス表やリソースの操作は、これまでどおりAxeが手元で処理します。
- BCDiceの版は、Axeと揃えます（いまは4.10.0）。

振らなかったときは、頼んだ人に`ROLL_REJECTED`（`{ identifier, reason }`）を返します。
`identifier`は、頼まれた結果の発言の識別子です。
同じ識別子の結果がもうある（か消してある）ときは、頼み直したものとみなして、ほかの確かめより先に、何も返さずに終えます。

| `reason`        | 起きるとき                                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invalid`       | 頼み方の形が違う（結果の発言の形、`suffix`の形、大きすぎるもの）、版が2の20乗を超える、部屋に置けるものの数（200000）に達した、タブの一覧の直下のタブでないところに置こうとした（振るあいだにタブが消されたときも） |
| `not-allowed`   | 見学者が、見学者の話せないタブで振ろうとした                                                                                                                                                                        |
| `rate-limited`  | 1つの接続から10秒に20回（`MAX_ROLLS_PER_WINDOW`）を超えて頼んだ                                                                                                                                                     |
| `busy`          | 部屋で振るのを待っているダイスが64個ある                                                                                                                                                                            |
| `not-a-command` | BCDiceのコマンドとして振れなかった（Axeが手元で振っても何も出ないもの）                                                                                                                                             |
| `failed`        | 振るあいだにサーバーで失敗した                                                                                                                                                                                      |

上限（コマンド4000文字、対象の名前128文字、1つの接続から10秒に20回）は、`contracts/protocol.ts`と`contracts/fixtures/limits.json`にあります。

## 見せないもの

見てはいけない人には、届けないか、一部を伏せて届けます。
期待値は`apps/cloudflare/contracts/fixtures/visibility.json`にあります。

| もの                                                                                               | 届けない・伏せる相手                                                         | どうするか                                                                                                    |
| -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| カード（`card`）の下の`image/front`・`common/name`・`common/text`・`detail`の下                    | 表が見えない人（裏向き、自分が覗いていない、自分の手札でもない）。GMは見える | 届けない                                                                                                      |
| 秘話（`attributes.to`が空でない`chat`）                                                            | 宛先と送り主（`from`か`originFrom`）のほか。GMも                             | 届けない                                                                                                      |
| シークレット（`attributes.tag`に`secret`がある`chat`）                                             | 送り主とGMのほか                                                             | `value`と、`attributes`の`dicebot`・`stamp`・`attachmentImageIdentifiers`・`editHistory`・`vnEmote`を空にする |
| 持ち主のいるダイス（`dice-symbol`）                                                                | 持ち主とGMのほか                                                             | `attributes.face`を空にする                                                                                   |
| 同じダイスの下の`common/name`（名前）                                                              | 同じ                                                                         | 届けない                                                                                                      |
| 公開を絞ったメモ（`text-note`の`disclosureMode`が`gm`か`selected`）の`common/title`・`common/text` | 見えない人（GMと持ち主は見える）                                             | 文字を`█`にする（空白はそのまま）                                                                             |
| 同じメモの`detail`の下                                                                             | 同じ                                                                         | 届けない                                                                                                      |
| タブ（`chat-tab`）の発言                                                                           | `plCanView`・`guestCanView`で見てよくない役割（`SystemTab`は誰にでも）       | 届けない                                                                                                      |
| リアクション（`chat-reaction`）                                                                    | その発言が届かない人                                                         | 届けない                                                                                                      |

データ要素は、親をたどった名前の道筋（根のデータ要素の下から、たとえば`image/front`）で見分けます。識別子の形（`front_<カードのID>`）では見分けません。
親がまだ届いていないもの（親の識別子のものを、サーバーがまだ持っていないもの）は、決まりを当てられないので、だれにも配りません。部屋の読み込みや複製では、子が親より先に届くことがあるためです。

- 見え方が変わったら（カードをめくる、手札に入れる、秘話の宛先を変える、タブを開く、役割が変わる）、見えるようになった人には`AUTHORITATIVE_OBJECT`で渡し、見えなくなった人には`WITHDRAW_GAME_OBJECT`で外させます。
- カタログ、`REQUEST_GAME_OBJECT`への答え、サーバーで振ったダイスも、同じ決まりで届けます。クライアントのカタログに見えないものや、親がまだ届いていないものがあれば（GMのほか）、`WITHDRAW_GAME_OBJECT`を返します。
- 見えないものに書こうとすると、`WITHDRAW_GAME_OBJECT`が返り、何も変わりません。見えないものは消せません。
- 伏せた形で持っているものを書き戻すと、伏せたところは置いてある中身に戻ります（ダイスを動かしても出目は消えない）。
- 伏せた形には、本物より少し小さい版（`minorVersion`を半分にしたもの）を付けます。カタログにも同じ版を載せます。見えるようになったとき、本物の版の方が新しいので、つないでいなかった人もカタログの交換で取り直せます。伏せた形を書き戻した人には、伏せた形をその版で返します。
- 伏せた形で持っている人が古い版で書いて負けたときは、置いてある方を`AUTHORITATIVE_OBJECT`で返します。伏せた形の版は本物より小さいので、`UPDATE_GAME_OBJECT`で返すと、送り主の版より低くて捨てられることがあるためです。
- 親が届いたときと、ものが別の親の下に移ったときは、子孫の見え方を比べ直します。見えるようになった人には`AUTHORITATIVE_OBJECT`で渡し、見えなくなった人には`WITHDRAW_GAME_OBJECT`で外させます。親を待っていた子は、親を送ってきた本人がもう持っているので、その人には送り返しません。ただし、親を待つあいだにカタログの交換で外させた子は、その人にも渡します。
- 消したものの子孫は、送り主から見えなかったものも一緒に消し、持っている人には`DELETE_GAME_OBJECT`を送ります。
- サーバーが差し込んだイベントは、ほかの人の束（`data`）に入ることがあります。誰からのイベントかは、束の`from`ではなく、イベントごとの`sendFrom`で見てください。

GMでない人は、書き込みで自分に見えるものを増やせません。
次の書き込みは配らず、送り主には置いてある方を`AUTHORITATIVE_OBJECT`で返して戻させます。

- データ要素の名前を変えたり、ものを別の親の下に移したりして、書いた人自身にそのものか子孫が今より見えるようになる書き込み
- 発言の`from`・`originFrom`を変える書き込み（GMのほかはだれも変えられない）
- ほかの人の手札（`location`が`hand:<ほかの人のuserId>`）にあるカードの、向き・持ち主・場所を変える書き込み。ただし、裏向きで、だれも覗いていない（`owner`が空の）まま自分の手札へ移すこと（ほかの人の手札から1枚引くこと）は通します
- タブ（`chat-tab`）の`plCanView`・`guestCanView`（だれが読めるか）を変える書き込み。だれが話せるか（`plCanSpeak`・`guestCanSpeak`）は変えられます
- タブを別の親の下へ移す書き込み（タブはタブの一覧の直下にだけ置く）
- いまそのメモが読めない人が、持ち主のいないメモを自分のものにする書き込み（GMだけのメモは取れない）

## 見学者が書けるもの

見学（`guest`）の人が書けるのは、次のものだけです。

- 自分の`PeerCursor`（書き換えと、消すこと）
- 見学者も話せるタブ（`chat-tab`の`attributes.guestCanSpeak`が`true`）への新しい発言（`chat`）。ダイスの結果のように`from`が本人でないものも書ける
- 自分の発言（`attributes`の`from`か`originFrom`が自分の`userId`）の書き直し

それ以外の`UPDATE_GAME_OBJECT`と`DELETE_GAME_OBJECT`は配らず、見学者の画面で戻させます。

| 書こうとしたもの               | 見学者に返すもの                         |
| ------------------------------ | ---------------------------------------- |
| サーバーが持っているもの       | `AUTHORITATIVE_OBJECT`（サーバーの中身） |
| 消したもの                     | `DELETE_GAME_OBJECT`                     |
| どちらでもない（新しく作った） | `WITHDRAW_GAME_OBJECT`                   |

## 接続を閉じる理由

サーバーは`error`を送ってから、close code `4000`、reasonに同じコードを付けて閉じます。
クライアントから閉じたときは、同じclose codeとreasonで閉じ返します（送れないcode、たとえば付けずに閉じたときの`1005`なら`1000`）。

| コード              | 起きるとき                                                                                                                                                                                                        | つなぎ直して直るか |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------: |
| `protocol-mismatch` | `hello`の`protocolVersion`がサーバーと違う。Axeを読み込み直して更新する                                                                                                                                           |                    |
| `room-not-found`    | 部屋が無い（作られていないか、消えた）。部屋を消しているあいだに来た接続も                                                                                                                                        |                    |
| `room-full`         | 部屋にいる人が32人に達している。部屋が受けるWebSocketが64本に達しているときも                                                                                                                                     |         ✅         |
| `wrong-password`    | パスワードが違うか、無い                                                                                                                                                                                          |                    |
| `hello-required`    | 最初のメッセージが`hello`でない                                                                                                                                                                                   |                    |
| `bad-message`       | MessagePackとして読めない、展開すると32MiBを超える、封筒の形が違う、`ping`でないテキストを送った。ほかの人のピアIDや、`System`・`System-BCDice`を名乗った。見学で使っていたピアIDの、ログインした本人が入ってきた |                    |
| `too-many-messages` | 10秒のあいだに2000を超えるフレームか、20000を超えるイベントを送った                                                                                                                                               |         ✅         |
| `replaced`          | 同じ人が同じピアIDで新しくつないだ。つなぎ直すと新しい方を追い出すので、つなぎ直さない                                                                                                                            |                    |
| `unauthorized`      | `accessToken`が無効か期限切れ、または`userId`がアカウントと違う。トークンを替えてつなぎ直す                                                                                                                       |         ✅         |
| `room-deleted`      | GMが部屋を削除した。部屋はもう無いので、つなぎ直さない                                                                                                                                                            |                    |

`accessToken`を付けずに、`acct_`で始まる`userId`か、この部屋にログインして入ったことのある`userId`を名乗ったときも、`unauthorized`で切ります。
同じ`userId`でログインした人が入ってきたときに閉じる見学の席も、`unauthorized`です。見学の席はトークンを持たないので、つなぎ直しても入れません（ログインしてから入り直す）。
つながったあと、アクセストークンが切れて1分を過ぎても`auth`が届かなかったときも同じです（→ [`auth`](#auth)）。
`hello`を送らないまま10秒を過ぎた接続は、`hello-required`で切ります（次に誰かがつないだときに）。

### 別の接続でつなぎ直してもらう

Vercel版は、`error`を送らずに、close code `1012`で閉じることがあります。

| reason   | 起きるとき                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------- |
| `rotate` | 接続を長く持てない基盤なので、つないでから`ROOM_SOCKET_SECONDS`（既定280秒）たった                 |
| `moved`  | 部屋を受け持つインスタンスが替わった（前のインスタンスが部屋を放したか、そのインスタンスが落ちた） |

クライアントは、すぐにつなぎ直します。ほかの人には、出たことも入ったことも見せません。
`rotate`で閉じた席は、15秒のあいだ残しておきます。そのあいだに同じ人が同じピアIDでつなぎ直せば、ほかの人に`leave`も`join`も届きません。
つなぎ直した`welcome`の`members`で、部屋にいる人を合わせ直します。

## 契約のフィクスチャ

`apps/cloudflare/contracts/`は、サーバー側が持ち主です。
Axeは同じ内容を写して使い、両側のテストが同じJSONを読みます。
npmには出していません。

| ファイル                   | 中身                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| `protocol.ts`              | 封筒の型、定数、エラーのコード、版を比べる関数（`judgeUpdate`）    |
| `fixtures/lww.json`        | 版を比べたときの期待値                                             |
| `fixtures/messages.json`   | 封筒の例。サーバーが受け付けるもの・断るもの・送るもの             |
| `fixtures/errors.json`     | 接続を閉じる理由ごとの、起きるときとサーバーが送るもの             |
| `fixtures/visibility.json` | 見え方の期待値。置いたものが、GM・持ち主・PL・見学からどう見えるか |
| `fixtures/events.json`     | サーバーとのあいだだけで使うイベントの例と、断る理由のすべて       |
| `fixtures/http.json`       | HTTPの要求と返事の例。サーバーのテストが、実際の返事と形を比べる   |
| `fixtures/limits.json`     | 両側で揃える上限と期間                                             |

封筒の形を変えたときは、`PROTOCOL_VERSION`を上げます。
版の違うAxeは`protocol-mismatch`で断られ、読み込み直すよう案内されます。
