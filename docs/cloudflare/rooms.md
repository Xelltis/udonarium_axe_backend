# 部屋のサーバー

Cloudflare版には、SkyWayを使わずに遊ぶための**部屋のサーバー**が入っています。
部屋ごとに1つのDurable Objectが、参加者のWebSocketを受けてやりとりを中継し、卓の状態を持ちます。

::: tip ベータです
Axe v1.68.0から、部屋のサーバーにつなげます。
Axeの`assets/config.json`で`transport`を`"server"`にし、`backend.url`をこのWorkerのURLにします（→ [Axe側の設定](/guide/client-config#サーバー版で配信するとき)）。
実際の卓で使った数はまだ多くありません。
:::

## SkyWay版との違い

|                    | SkyWay版                                   | サーバー版                                              |
| ------------------ | ------------------------------------------ | ------------------------------------------------------- |
| つながりかた       | 参加者どうしが直接つながる（フルメッシュ） | 全員が部屋のサーバーにつながる                          |
| 卓の状態を持つ場所 | 参加者のブラウザだけ                       | 部屋のサーバーと、参加者のブラウザ                      |
| 全員が抜けたとき   | 卓の状態は消える                           | 部屋のサーバーに残る（最後の1人が抜けて24時間で消える） |
| 要るもの           | トークン発行サーバー（PHP版かVercel版）    | Cloudflare版だけ                                        |
| 部屋の一覧         | SkyWayのロビーから作る                     | Cloudflare版が持つ                                      |
| パスワード         | ピアIDに埋めたダイジェストを各自が照らす   | 部屋のサーバーが照らす（ハッシュだけを持つ）            |

どちらで配信するかは、Axeの配信ごとに選びます。
1つの配信の中で、部屋ごとに切り替えることはしません。

## しくみ

```text
Axe（参加者ごと）
 │  POST /v1/rooms          … 部屋を作る
 │  GET  /v1/rooms          … 部屋の一覧
 │  GET  /v1/rooms/<鍵>     … 部屋を鍵で1つ引く
 │  DELETE /v1/rooms/<鍵>   … 部屋を削除する（GMだけ）
 │  GET  /v1/rooms/<鍵>/ws  … 部屋に入る（WebSocket）
 └─ HEAD・GET・PUT /v1/rooms/<鍵>/assets/<SHA-256>
                            … 部屋のアセット（画像と音声）
        │
        ▼
Worker ──▶ 部屋のDurable Object（部屋ごとに1つ。SQLiteに状態を置く）
       ├─▶ ロビーのDurable Object（Workerに1つ。部屋の一覧）
       └─▶ R2のバケット（部屋のアセット。rooms/<鍵>/<SHA-256>）
```

1. 部屋を作ると、Workerが128ビットの乱数で**部屋の鍵**（`roomKey`）を決め、その名前のDurable Objectを作ります。表示用の3文字のID（`roomId`）も付けます。
2. 参加者は、部屋の鍵のURLにWebSocketでつなぎ、最初に`hello`を送ります。パスワードのある部屋なら、ここでサーバーが照らします。
3. 入れたら、サーバーは部屋にいる人の一覧と、自分が持っているオブジェクトの一覧（カタログ）を送ります。
4. あとは、参加者が送ったイベントを、ほかの参加者へ中継します。

### サーバーは「全部を持っているピア」

Axeは、卓のオブジェクトを参加者どうしで見せ合い（カタログの交換）、足りないものを取り寄せて同期しています。
部屋のサーバーは、この仕組みに**もう1人のピア**（`@authority`）として加わります。
カタログの交換はこのピアとだけ行うので、参加者が増えても交換の回数は増えません。

- 入ってきた人がサーバーより新しいものを持っていれば、サーバーが取り寄せます。
- サーバーの方が新しいものは、入ってきた人がサーバーから取り寄せます。
- 消したオブジェクトを持っていれば、サーバーが消させます。

### 新しい方を勝たせる

オブジェクトを書き換えるイベント（`UPDATE_GAME_OBJECT`）は、サーバーが持っているものと版を比べてから配ります。
版は、書き換えた回数と、0以上1未満の乱数の和です。Axeが参加者どうしで比べるのと同じ決まりです。

| 届いた版                 | サーバーがすること                     |
| ------------------------ | -------------------------------------- |
| 持っているものより新しい | 置き換えて、ほかの全員に配る           |
| 持っているものと同じ     | 何もしない                             |
| 持っているものより古い   | 配らず、持っている方を送り主に送り返す |
| 消したオブジェクト       | 配らず、送り主に消させる               |

伏せた形で持っている人が古い版で書いてきたときは、置いてある方を`AUTHORITATIVE_OBJECT`で返します（→ [見せないもの](/cloudflare/protocol#見せないもの)）。

版を一度に大きく上げる書き込みは受けません。1回の書き込みで上げてよい回数は2の20乗までで、初めて置くものの回数も2の20乗までです。上限（2の50乗）まで上げて、だれにも書き換えられなくすることを防ぐためです。0より小さい回数と、-1から1の外の乱数も受けません。Axeが書くたびに1ずつ上げる版は、これに当たりません。

消したオブジェクトには、その印（tombstone）を残します。
印があるあいだは、つなぎ直した人が古い写しを持っていても、消したものは生き返りません。
印は1つの部屋に10万件までで、超えたら古いものから8万件まで減らします。印を減らしたものは、古い写しを持つ人がつなぎ直すと戻ることがあります。
印を残すかは、送られてきた種類名ではなく、置いてあるものの種類で決めます（カーソルには残しません）。
部屋を読み込み直すときのように、消したものを同じ名前で戻したいときは、Axeが先に「戻す」と知らせ（`FORGET_DELETED_OBJECTS`）、サーバーも印を外します。

### カーソルは、その人がいるあいだだけ

参加者ごとのカーソル（`PeerCursor`）は、その人が部屋にいるあいだだけ持ちます。
カーソルを書いたり消したりできるのは、その人の席だけです。サーバーは、カーソルのピアID・ユーザーID・役割を席の値にして置きます。
その人が抜けると、サーバーは持っていたカーソルを消し、ほかの参加者には「抜けた」とだけ知らせます。
カーソルには消した印を残さないので、同じ人が入り直せば、またカーソルを出せます。

Workerが落ちると、出ていく知らせが届かないまま、その人のカーソルが残ります。
そうしたカーソルは、だれかが入ってきたときと1時間ごとの見回りで消し、ほかの参加者にも消させます。

### 同じ人が2本つないだら

同じ人が同じピアIDで新しくつないだら、古い方を閉じます（`replaced`）。
回線が切れたのにサーバーがまだ気づいていない接続が、幽霊のように残らないためです。
SkyWay版では、こうした接続が60秒ほど残ることがありました。
古い接続のカーソルは消して、ほかの参加者にも消させます。読み直したページのカーソルは、別の識別子になるためです。

同じ人かどうかは、ユーザーIDとログインの有無で見ます。
ほかの人のピアIDを名乗る接続は、`bad-message`で断ります。
入れると、その人を追い出して成り代われてしまうからです。
ただし、ログインした人のピアIDを見学が先に取っていたら、その人が入ってきたときに見学のほうを外します。
ピアIDはユーザーIDから作るので、ログインした人のピアIDを持てるのはその人だけだからです。

### 画像と音声は部屋のアセットに置く

画像と音声は、部屋のアセットとして、部屋ごとにR2に置きます。
読み書きできるのはその部屋の席だけで、部屋のサーバーが席に渡すトークンを使います（→ [部屋のアセット](/cloudflare/protocol#部屋のアセット)）。
部屋のアセットに無いものは、持っている人から部屋のサーバーの中継で受け取ります。

## 卓の状態の置き場所

部屋のDurable Objectは、卓の状態をSQLiteに置きます。

- しばらくやりとりが無いと、Durable Objectは眠り（Hibernation）、メモリの中身は消えます。接続は切れず、次のメッセージで起き直します。そのため、接続中でも状態はSQLiteに書いています。
- 書き込みは、オブジェクトごとに1秒ぶんまとめてから書きます。コマをドラッグして何十回も書き換えても、書くのは1回で済みます。落ちたときに失うのは最大で1秒ぶんで、それもつなぎ直したときのカタログの交換で戻ります。
- 1MiBを超えるオブジェクト（大きな白板など）は、行を分けて置きます。SQLiteの1行は2MBまでだからです。
- 書けないもの（SQLiteの1行の上限を超えたものなど）があったときは、それだけを捨て、索引をSQLiteにあるとおりに戻します。

最後の1人が抜けてから`ROOM_RETENTION_HOURS`（既定24時間）が過ぎると、部屋を一覧から外し、置いたものと部屋のアセット（画像と音声）をすべて消します。
その前に誰かが入れば、消す予定は取り消します。
作ったまま誰も入らなかった部屋も、同じ時間で消えます。
部屋のGMが削除したときは、待たずに同じように消し、部屋にいた人の接続を閉じます。

人がいるあいだは、1時間ごとに、実際につながっている人を数え直します。
Workerが落ちると、出ていく知らせが届かないまま接続が切れます。そのときも、一覧の人数を直し、そこから保持期間を数えて消します。

ログインした席のトークンが切れて1分を過ぎたときも、見回りでその席を外します（→ [`auth`](/cloudflare/protocol#auth)）。
見回りの時刻は、部屋でいちばん早く切れるトークンに合わせて早めることがあります。
外れて部屋が空になれば、ふつうに出ていったときと同じく、そこから保持期間を数えます。

## 上限

| 項目                       | 上限                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| 1つの部屋に入れる人数      | 32人                                                                                          |
| 1つの部屋が受けるWebSocket | 64本（`hello`を送る前のものも含む）                                                           |
| `hello`を送るまでの時間    | 10秒。過ぎたものは、新しい接続が来たときに閉じる                                              |
| 1つの接続が送れるフレーム  | 10秒に2000まで。超えると切る                                                                  |
| 1つの接続が送れるイベント  | 10秒に20000まで。超えると切る                                                                 |
| 1つのフレームの大きさ      | 展開したあとで32MiBまで                                                                       |
| 1回に送れるイベント        | 4096まで                                                                                      |
| サーバーで振るダイス       | 1つの接続から10秒に20回、部屋全体で待てるのは64回まで。超えたものは振らず、頼んだ人に知らせる |
| 1つの部屋に置けるもの      | 200000まで。消した印は100000を超えたら古いものから80000まで減らす                             |
| 親の識別子                 | 256文字まで                                                                                   |
| 宛先などの見え方の手がかり | 16KiBまで                                                                                     |
| 部屋の名前                 | 1〜255文字                                                                                    |
| パスワード                 | 64文字まで                                                                                    |
| 部屋を作る・削除する・入る | 送信元ごとに、合わせて1分30回まで                                                             |

## 見えない情報

SkyWay版では、裏向きのカードの表や他人宛ての秘話も、データとしては全員のブラウザに届いていて、画面に出さないだけでした。
サーバー版では、見てはいけない人には、そもそも届けません。

- **カード**：表が見えない人（裏向きで、自分が覗いておらず、自分の手札でもない人）には、表の絵を指すデータ要素・名前・表の文字・詳細を届けません。GMには届けます。絵のファイルそのものは、部屋の画像として全員が受け取ります（→ [わざと隠さないもの](#わざと隠さないもの)）。
- **秘話**：宛先と送り主のほかには届けません。Axeと同じく、GMにも届けません。
- **シークレットダイス**：振った人とGMのほかには、結果の文面と出目を空にして届けます。「シークレットダイス」の行だけが見えます。振った人かGMが公開すると、全員に結果が届きます。
- **持ち主のいるダイス**：持ち主とGMのほかには、出目を空にして届けます。ダイスの名前も届けません。
- **公開を絞ったメモ**：見えない人には、題と本文を█にして届けます（Axeが伏せて描くのと同じ形）。
- **タブ**：PLや見学者に見せないタブの発言は、その役割には届けません。

見え方はユーザーIDで決まります。
見学者（ログインしていない人）は、ログインした人のユーザーID（`acct_`で始まるもの）と、この部屋にログインして入ったことのあるユーザーIDを名乗れません。そのため、カーソルに見えるユーザーIDを名乗って、その人の手札や秘話をのぞくことはできません。

部屋の読み込みや複製では、子が親より先に届くことがあります。
親がまだ届いていないものは、見え方を決められないので、だれにも配りません。親が届いてから見え方を確かめ、見てよい人に渡します。

GMでない人は、書き込みで自分に見えるものを増やせません。
データ要素の名前を変えたり、ものを別の親の下に移したり、まだ無い親の下へ移してからその親を作ったりして伏せたものを手に入れることも、発言の送り主を変えることも、ほかの人の手札にあるカードの向きや持ち主を変えることも、読めないメモを自分のものにすることも、タブをPLや見学者に見せるかを変えることもできません。
ほかの人の手札のカードは、伏せたまま自分の手札へ引くこと（Axeの「相手の手札から引く」）だけができます。

カードをめくったり手札に入れたり、秘話の宛先を変えたり、役割が変わったりして見え方が変わると、見えるようになった人に渡し、見えなくなった人の手元から外させます。
細かい決まりは[部屋のプロトコル](/cloudflare/protocol#見せないもの)にあります。

### わざと隠さないもの

次のものは、隠すとプレイヤーの画面で動くしくみが働かなくなるので、これまでどおり全員に届けます（画面には出しません）。

- **GMにだけ見せるスイッチと地形**：罠は、駒を動かした人の画面で発動します。視界も、その人の画面で計算しています。プレイヤーの手元に無いと、プレイヤーの駒で罠が動かず、視界も遮られません。隠すには、発動をサーバーかGMの画面に移す必要があり、いまはそうしていません。
- **GMにだけ見せるエフェクト**：エフェクトを使うと、使った人が識別子だけを送り、各自の画面が手元のエフェクトをその識別子で引いて描きます。GMにだけ見せる設定（`gmOnly`）は、選べる人をGMに絞るもので、見た目を隠すものではありません。届けないと、GMが使ったエフェクトがプレイヤーの画面に出ません。
- **キャラクターの詳細**：公開を絞ったキャラクターでも、プレイヤーがリソースのコマンド（`:HP-5`など）でHPを減らすときに、手元の値を使います。
- **名前を隠したキャラクターの名前**：名前は各自の画面で隠しています。サーバーはキャラクターの中を見ません。
- **視界と霧**：計画どおり、サーバーでは計算しません。
- **画像と音声のファイル**：部屋に置いた画像と音声は、部屋の席ならだれでも受け取れます（入ったときに部屋の一覧から取りに行きます）。伏せたカードで隠すのは「どのカードの表がどの絵か」だけで、絵のファイルは見学者を含めて全員の手元に届きます。GMが「秘匿」にした画像も、選ぶ一覧に出ないだけです。
- **カードとダイスの公開範囲で絞った詳細**：Axeは、公開範囲の外の人にシートを開かせません。サーバーはこの範囲を見ずに届けます（メモの公開範囲だけを見ます）。

そのため、改造したAxeなら、GMにだけ見せるエフェクトの中身や、隠した罠の場所と中身を読めます。

チャットのダイスは、サーバーがBCDiceで振ります（→ [サーバーで振るダイス](/cloudflare/protocol#サーバーで振るダイス)）。
