# 部屋のサーバー

Cloudflare版には、SkyWayを使わずに遊ぶための**部屋のサーバー**が入っています。
部屋ごとに1つのDurable Objectが、参加者のWebSocketを受けてやりとりを中継し、卓の状態を持ちます。

::: tip ベータです
Axe v1.68.0から、部屋のサーバーにつなげます。
Axeの`assets/config.json`で`transport`を`"server"`にし、`backend.url`をこのWorkerのURLにします（→ [Axe側の設定](/guide/client-config#サーバー版で配信するとき)）。
実際の卓で使った数はまだ多くありません。
:::

## SkyWay版との違い

|                    | SkyWay版                                   | サーバー版                                              |
| ------------------ | ------------------------------------------ | ------------------------------------------------------- |
| つながりかた       | 参加者どうしが直接つながる（フルメッシュ） | 全員が部屋のサーバーにつながる                          |
| 卓の状態を持つ場所 | 参加者のブラウザだけ                       | 部屋のサーバーと、参加者のブラウザ                      |
| 全員が抜けたとき   | 卓の状態は消える                           | 部屋のサーバーに残る（最後の1人が抜けて24時間で消える） |
| 要るもの           | トークン発行サーバー（PHP版かVercel版）    | Cloudflare版だけ                                        |
| 部屋の一覧         | SkyWayのロビーから作る                     | Cloudflare版が持つ                                      |
| パスワード         | ピアIDに埋めたダイジェストを各自が照らす   | 部屋のサーバーが照らす（ハッシュだけを持つ）            |

どちらで配信するかは、Axeの配信ごとに選びます。
1つの配信の中で、部屋ごとに切り替えることはしません。

## しくみ

```text
Axe（参加者ごと）
 │  POST /v1/rooms          … 部屋を作る
 │  GET  /v1/rooms          … 部屋の一覧
 └─ GET  /v1/rooms/<鍵>/ws  … 部屋に入る（WebSocket）
        │
        ▼
Worker ──▶ 部屋のDurable Object（部屋ごとに1つ。SQLiteに状態を置く）
       └─▶ ロビーのDurable Object（Workerに1つ。部屋の一覧）
```

1. 部屋を作ると、Workerが128ビットの乱数で**部屋の鍵**（`roomKey`）を決め、その名前のDurable Objectを作ります。表示用の3文字のID（`roomId`）も付けます。
2. 参加者は、部屋の鍵のURLにWebSocketでつなぎ、最初に`hello`を送ります。パスワードのある部屋なら、ここでサーバーが照らします。
3. 入れたら、サーバーは部屋にいる人の一覧と、自分が持っているオブジェクトの一覧（カタログ）を送ります。
4. あとは、参加者が送ったイベントを、ほかの参加者へ中継します。

### サーバーは「全部を持っているピア」

Axeは、卓のオブジェクトを参加者どうしで見せ合い（カタログの交換）、足りないものを取り寄せて同期しています。
部屋のサーバーは、この仕組みに**もう1人のピア**（`@authority`）として加わります。
カタログの交換はこのピアとだけ行うので、参加者が増えても交換の回数は増えません。

- 入ってきた人がサーバーより新しいものを持っていれば、サーバーが取り寄せます。
- サーバーの方が新しいものは、入ってきた人がサーバーから取り寄せます。
- 消したオブジェクトを持っていれば、サーバーが消させます。

### 新しい方を勝たせる

オブジェクトを書き換えるイベント（`UPDATE_GAME_OBJECT`）は、サーバーが持っているものと版を比べてから配ります。
版は、書き換えた回数と、0以上1未満の乱数の和です。Axeが参加者どうしで比べるのと同じ決まりです。

| 届いた版                 | サーバーがすること                     |
| ------------------------ | -------------------------------------- |
| 持っているものより新しい | 置き換えて、ほかの全員に配る           |
| 持っているものと同じ     | 何もしない                             |
| 持っているものより古い   | 配らず、持っている方を送り主に送り返す |
| 消したオブジェクト       | 配らず、送り主に消させる               |

消したオブジェクトは、その印（tombstone）を部屋がなくなるまで残します。
つなぎ直した人が古い写しを持っていても、消したものが生き返ることはありません。
部屋を読み込み直すときのように、消したものを同じ名前で戻したいときは、Axeが先に「戻す」と知らせ（`FORGET_DELETED_OBJECTS`）、サーバーも印を外します。

### カーソルは、その人がいるあいだだけ

参加者ごとのカーソル（`PeerCursor`）は、その人が部屋にいるあいだだけ持ちます。
その人が抜けると、サーバーは持っていたカーソルを消し、ほかの参加者には「抜けた」とだけ知らせます。
カーソルには消した印を残さないので、同じ人が入り直せば、またカーソルを出せます。

### 同じ人が2本つないだら

同じ人が同じピアIDで新しくつないだら、古い方を閉じます（`replaced`）。
回線が切れたのにサーバーがまだ気づいていない接続が、幽霊のように残らないためです。
SkyWay版では、こうした接続が60秒ほど残ることがありました。

同じ人かどうかは、ユーザーIDとログインの有無で見ます。
ほかの人のピアIDを名乗る接続は、`bad-message`で断ります。
入れると、その人を追い出して成り代われてしまうからです。

## 卓の状態の置き場所

部屋のDurable Objectは、卓の状態をSQLiteに置きます。

- しばらくやりとりが無いと、Durable Objectは眠り（Hibernation）、メモリの中身は消えます。接続は切れず、次のメッセージで起き直します。そのため、接続中でも状態はSQLiteに書いています。
- 書き込みは、オブジェクトごとに1秒ぶんまとめてから書きます。コマをドラッグして何十回も書き換えても、書く行は1つで済みます。落ちたときに失うのは最大で1秒ぶんで、それもつなぎ直したときのカタログの交換で戻ります。
- 1MiBを超えるオブジェクト（大きな白板など）は、行を分けて置きます。SQLiteの1行は2MBまでだからです。

最後の1人が抜けてから`ROOM_RETENTION_HOURS`（既定24時間）が過ぎると、部屋を一覧から外し、置いたものをすべて消します。
その前に誰かが入れば、消す予定は取り消します。
作ったまま誰も入らなかった部屋も、同じ時間で消えます。

人がいるあいだは、1時間ごとに、実際につながっている人を数え直します。
Workerが落ちると、出ていく知らせが届かないまま接続が切れます。そのときも、一覧の人数を直し、そこから保持期間を数えて消します。

## 上限

| 項目                       | 上限                                |
| -------------------------- | ----------------------------------- |
| 1つの部屋に入れる人数      | 32人                                |
| 1つの部屋が受けるWebSocket | 64本（`hello`を送る前のものも含む） |
| `hello`を送るまでの時間    | 10秒。過ぎたものは、新しい接続が来たときに閉じる |
| 1つの接続が送れるフレーム  | 10秒に2000まで。超えると切る        |
| 1つの接続が送れるイベント  | 10秒に20000まで。超えると切る       |
| 1つのフレームの大きさ      | 展開したあとで32MiBまで             |
| 1回に送れるイベント        | 4096まで                            |
| サーバーで振るダイス       | 1つの接続から10秒に20回、部屋全体で待てるのは64回まで。超えたものは振らない |
| 1つの部屋に置けるもの      | 200000まで。消した印は100000を超えたら古いものから減らす |
| 親の識別子                 | 256文字まで                         |
| 宛先などの見え方の手がかり | 16KiBまで                           |
| 部屋の名前                 | 1〜255文字                          |
| パスワード                 | 64文字まで                          |
| 部屋を作る・部屋に入る     | 送信元ごとに、合わせて1分30回まで   |

## 見えない情報

SkyWay版では、裏向きのカードの表や他人宛ての秘話も、データとしては全員のブラウザに届いていて、画面に出さないだけでした。
サーバー版では、見てはいけない人には、そもそも届けません。

- **カード**：表が見えない人（裏向きで、自分が覗いておらず、自分の手札でもない人）には、表の絵・名前・表の文字・詳細を届けません。GMには届けます。
- **秘話**：宛先と送り主のほかには届けません。Axeと同じく、GMにも届けません。
- **シークレットダイス**：振った人とGMのほかには、結果の文面と出目を空にして届けます。「シークレットダイス」の行だけが見えます。振った人かGMが公開すると、全員に結果が届きます。
- **持ち主のいるダイス**：持ち主とGMのほかには、出目を空にして届けます。
- **公開を絞ったメモ**：見えない人には、題と本文を█にして届けます（Axeが伏せて描くのと同じ形）。
- **タブ**：PLや見学者に見せないタブの発言は、その役割には届けません。

見え方はユーザーIDで決まります。
見学者（ログインしていない人）は、ログインした人のユーザーID（`acct_`で始まるもの）を名乗れないので、カーソルに見えるユーザーIDを名乗って、その人の手札や秘話をのぞくことはできません。

カードをめくったり手札に入れたり、秘話の宛先を変えたり、役割が変わったりして見え方が変わると、見えるようになった人に渡し、見えなくなった人の手元から外させます。
細かい決まりは[部屋のプロトコル](/cloudflare/protocol#見せないもの)にあります。

### わざと隠さないもの

次のものは、隠すとプレイヤーの画面で動くしくみが働かなくなるので、これまでどおり全員に届けます（画面には出しません）。

- **GMにだけ見せるスイッチと地形**：罠が動くかや視界は、駒を動かした人の画面で計算しています。プレイヤーの手元に無いと、罠が動かず、視界も遮られません。
- **GMにだけ見せるエフェクト**：エフェクトは、使った人がIDだけを送り、受け取った人が手元のエフェクトを見て描きます。
- **キャラクターの詳細**：公開を絞ったキャラクターでも、プレイヤーがリソースのコマンド（`:HP-5`など）でHPを減らすときに、手元の値を使います。
- **視界と霧**：計画どおり、サーバーでは計算しません。

チャットのダイスは、サーバーがBCDiceで振ります（→ [サーバーで振るダイス](/cloudflare/protocol#サーバーで振るダイス)）。
