# Cloudflare版

Cloudflare Workersの上で動く、Axeの**サーバー版**のWorkerです。
2つのものを受け持っています。

- **アセットサーバー**：画像と音声の置き場。SkyWay版の配信に足せば、卓の参加者はP2Pの代わりにここから画像と音声を受け取れます。
- **部屋のサーバー**：部屋ごとのDurable Objectが、参加者のやりとりを中継し、卓の状態を持ちます。SkyWayもトークン発行サーバーも使わずに遊ぶためのものです（→ [部屋のサーバー](/cloudflare/rooms)）。

部屋に入るときは、GMとPLはDiscordでログインし、ログインしていない人は見学になります（→ [ログインと役割](/cloudflare/login)）。
部屋のサーバーとログインには、Axe v1.68.0から対応しています（ベータ）。Axeの設定は[Axe側の設定](/guide/client-config#サーバー版で配信するとき)にあります。

## アセットサーバーのしくみ

画像と音声は、**中身のSHA-256**を名前にして、Cloudflareのファイル置き場（R2）に置きます。
同じ中身なら名前も同じになるので、何度上げても1つしか置かれません。

```text
GM（画像を足した人）
 ├─ HEAD /v1/assets/<SHA-256> … 置かれているか確かめる
 └─ PUT  /v1/assets/<SHA-256> … 無ければ置く

ほかの参加者
 └─ GET  /v1/assets/<SHA-256> … 持っていない画像を受け取る（無ければP2Pで頼む）
```

1. GMが画像を足したり部屋を読み込んだりすると、Axeは画像の中身からSHA-256を計算し、置かれているかを確かめます。無ければ置きます。
2. ほかの参加者は、持っていない画像をまずアセットサーバーから受け取ります。届いた中身のハッシュが名前と合うことも確かめます。
3. アセットサーバーに無いときや、つながらないときは、これまでどおり持っている人にP2Pで頼みます。

アセットサーバーは、なくても遊べるように作ってあります。
止めたり、`config.json`の`assets.url`を空にしたりしても、画像と音声はP2Pで配られます。

## 特徴

- **ハッシュの照合**：PUTの本文のSHA-256が名前と合わなければ置きません。照合はR2が書き込みながら行います。
- **形式の判定**：画像（PNG・JPEG・GIF・BMP・WebP・AVIF・HEIC・SVG）と音声（MP3・WAV・Ogg・FLAC・M4A・AAC）だけを受け付けます。宣言されたContent-Typeではなく、中身の先頭のバイトで判定します。
- **大きさの上限**：画像は2MiB、音声は10MiBまでです（Axeが読み込める上限と同じ）。
- **キャッシュ**：同じデータセンターからの2回目以降のGETは、CloudflareのCache APIから返し、R2を読みません。
- **保持期間**：置いてから30日（変えられる）で消えます。使われていれば、次に部屋を読み込んだときにまた上がります。
- **レート制限**：送信元ごとに、新しく置くのは1分100件、R2から読むのは1分600件までです。
- **何台でも置ける**：同じCloudflareアカウントに何台置いても、R2のバケット、部屋、レート制限はWorkerごとに分かれます。

## 必要なもの

- Cloudflareのアカウント（無料プランで動きます）
- アカウントでのR2の利用申し込み（アカウントに一度だけ。無料枠があります）
- 本番で使うなら、Cloudflareで管理している独自ドメイン（キャッシュを効かせるため）

部屋のサーバーに使うDurable Objectsは、無料プランでも使えます。
デプロイのときに作られるので、前もって申し込むものはありません。
