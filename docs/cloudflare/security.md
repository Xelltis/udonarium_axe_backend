# 安全のしくみ（Cloudflare版）

このページでは、Cloudflare版（アセットサーバー）が何を守り、何を守らないのかを説明します。
アセットサーバーを置くかどうかを決めるときや、置いたあとの運用の参考にしてください。

## 守っていること

### 名前と中身の照合

画像と音声は、中身のSHA-256を名前にして置きます。
PUTの本文のハッシュが名前と合わなければ、何も置きません。
照合はR2が書き込みながら行うので、途中で中身をすり替えることはできません。

受け取る側のAxeも、届いた中身のハッシュが名前と合うかを確かめます。
合わなければ捨てて、持っている人にP2Pで頼みます。

### 形式の判定

置けるのは、受け付ける画像と音声だけです。
宣言された`Content-Type`は信じず、中身の先頭のバイトを見て形式を決め、配るときの`Content-Type`もそれにします。
これは、ブラウザがスクリプトとして扱えるもの（HTMLなど）を配らないためです。

- **SVGは受け付けません。** SVGは中にスクリプトを書けるためです。SVGの画像は、これまでどおりP2Pで配られます。
- **MP4やMOVの動画は受け付けません。** M4Aと同じ入れ物ですが、音声として置ける大きさ（10MiB）に収まる動画を、音声として置かせないためです。
- 判定するのは先頭の印だけで、続く中身が壊れていないことまでは確かめません。

配るときは`X-Content-Type-Options: nosniff`を付け、ブラウザが中身から形式を推測し直さないようにしています。

### 大きさの上限

画像は2MiB、音声は10MiBまでです。
`Content-Length`がこれを超えるPUTは、本文を読む前に断ります。

### 保持期間

置いたものは、既定で30日を過ぎると`404`になり、少しずつバケットから消えます。
置かれた量が際限なく増えることはありません。

## 守っていないこと

### 置いたものは、名前を知っていれば誰でも読める

GETとHEADは、どのページからでも受けます。
名前（SHA-256）は中身から計算されるので、中身を持っていない人には推測できません。
ただし、次のことには気をつけてください。

- 同じファイルを持っている人は、それが置かれているかを確かめられます。
- 部屋のセーブデータなどから名前が漏れれば、その画像は誰でも読めます。

メンバー以外から完全に隠したい素材があるときは、アセットサーバーを使わず、P2Pだけで配ってください（`config.json`の`assets.url`を空にする）。

### 置ける人は限っていない

PUTは、`ACCESS_CONTROL_ALLOW_ORIGIN`に書いたOriginのページからだけ受けます。
ただし、`Origin`ヘッダーはブラウザ以外（`curl`など）からなら好きな値を付けられます。
これは、ほかのサイトに置かれたAxeからあなたのアセットサーバーが使われるのを防ぐためのもので、置ける人を限るものではありません。

その代わりに、次の制限で置かれる量を抑えています。

- 新しく置くPUTは、送信元ごとに1分100件まで（IPv6は/64ごと）
- 保持期間（既定30日）を過ぎたものは消える

ログインした人だけが置けるようにするのは、サーバー版の部屋ができてからです。
サーバー版では、GMとPLはDiscordなどでログインし、その証明（セッショントークン）をアップロードにも求める予定です（→ [今後の計画](/guide/roadmap)）。

### Workerを呼ぶ回数そのもの

Workerの中のレート制限は、Workerが呼ばれたあとに働きます。
呼ばれた回数そのものは、Workerの中では減らせません。
読み出しを繰り返されるのが心配なときは、カスタムドメインのゾーンに、Cloudflareの**WAFのレート制限ルール**を足してください。
WAFはWorkerより手前で働くので、Workerが呼ばれる前に止められます。

## 気になることを見つけたら

脆弱性を見つけたときは、公開のIssueには書かず、[GitHub Security Advisory](https://github.com/Xelltis/udonarium_axe_backend/security/advisories/new)から非公開で知らせてください。
