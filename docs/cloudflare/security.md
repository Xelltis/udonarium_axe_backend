# 安全のしくみ（Cloudflare版）

このページでは、Cloudflare版（部屋のサーバーと、部屋に置く画像と音声）が何を守り、何を守らないのかを説明します。
置くかどうかを決めるときや、置いたあとの運用の参考にしてください。

## 守っていること

### 画像と音声は、その部屋の席だけが読み書きできる

画像と音声は、部屋のアセットとして部屋ごとに分けて置きます。
R2の名前は`rooms/<部屋の鍵>/<SHA-256>`です。
読むのも置くのも、その部屋の席にいる人だけです。

どのリクエストにも、`Authorization: Bearer <アセットのトークン>`が要ります。
このトークンは、部屋のサーバーが、部屋に入った席に`welcome`で渡します（→ [部屋のアセットのトークン](/cloudflare/protocol#部屋のアセットのトークン)）。
中身は部屋の鍵、その席の役割とユーザーIDで、`SESSION_SECRET`で署名し（HS256）、15分で切れます。
読む（HEAD・GET）のは、その部屋の席ならだれでも（GM・PL・見学）できます。
置く（PUT）のはGMとPLだけです。

- トークンが無い、切れた、ほかの部屋のもの、ログインのアクセストークンを付けた、のどれかなら`401 asset-token-required`を返します。
- 見学のトークンで置こうとすると`403 not-a-player`を返します。
- 置くときは、部屋がまだあり、その人がいまGMかPLとして席にいるかを部屋のサーバーに尋ねます。部屋が無ければ`404 room-not-found`、見学に変えられているか抜けていれば`403 not-a-player`を返します。トークンの期限が残っていても、削除した部屋には置けず、見学に変えられた人や抜けた人も置けません。

そのため、名前（SHA-256）を知っているだけでは読めません。
部屋の鍵は招待リンクに載り、部屋の一覧もだれにでも部屋の鍵を返します。
鍵を知っていてもトークンが無ければ読めませんが、パスワードの無い部屋なら、だれでも見学で入ってトークンを受け取れます（→ [部屋の鍵を知っていれば入れる](#部屋の鍵を知っていれば入れる)）。
部屋を抜けた人が読めるのは、持っているトークンが切れるまで（最長15分）です。

同じデータセンターのキャッシュ（Cache API）から返すときも、先にトークンを確かめます。
応答には`Cache-Control: private`を付け、ブラウザには置かせても、共有のキャッシュには置かせません。

### 名前と中身の照合

画像と音声は、中身のSHA-256を名前にして置きます。
PUTの本文のハッシュが名前と合わなければ、何も置きません。
照合はR2が書き込みながら行うので、途中で中身をすり替えることはできません。

受け取る側のAxeも、届いた中身のハッシュが名前と合うかを確かめます。
合わなければ捨てて、持っている人から部屋のサーバーの中継で受け取ります。

### 形式の判定

置けるのは、受け付ける画像と音声だけです。
宣言された`Content-Type`は信じず、中身の先頭のバイトを見て形式を決め、配るときの`Content-Type`もそれにします。
これは、ブラウザがスクリプトとして扱えるもの（HTMLなど）を配らないためです。

- **SVGは受け付けますが、サンドボックスに入れて配ります。** 下の節で説明します。
- **MP4やMOVの動画は受け付けません。** M4Aと同じ入れ物ですが、音声として置ける大きさ（10MiB）に収まる動画を、音声として置かせないためです。
- 判定するのは先頭の印だけで、続く中身が壊れていないことまでは確かめません。

配るときは`X-Content-Type-Options: nosniff`を付け、ブラウザが中身から形式を推測し直さないようにしています。

### SVGはサンドボックスに入れて配る

SVGは画像ですが、中に`<script>`を書けます。
Axeは`<img>`で読むので、そのときはスクリプトは動きません。
部屋のアセットは読むのにもトークンが要るので、URLをブラウザで開いても`401`が返るだけです。
それでも、トークンを付けて文書として開かれたときに備え、二重の守りとして次の手を取ります。

そこでSVGを配るときは、次の`Content-Security-Policy`を付けます。

```http
Content-Security-Policy: default-src 'none'; img-src data:; style-src 'unsafe-inline'; sandbox
```

- `sandbox`で、スクリプトを止め、文書を一時的な別のOriginとして扱わせます。
- `default-src 'none'`で、外のものを読みに行かせません。描くのに要る、埋め込みの画像（`data:`）と`style`属性だけを通します。

あわせて、**このWorkerを置くドメインではcookieを使わないでください。**
Axeやログインの画面とは別のホスト名（例：`backend.example.com`）にし、親のドメインに向けたcookie（`Domain=example.com`）も置かないようにします。
万一スクリプトが動いても、盗めるものが無いようにするためです。

### 大きさの上限

画像は2MiB、音声は10MiBまでです。
`Content-Length`がこれを超えるPUTは、本文を読む前に断ります。

### 部屋と一緒に消す

部屋のアセットは、部屋と一緒に消します。
部屋のGMが部屋を削除したときと、最後の1人が抜けて`ROOM_RETENTION_HOURS`（既定24時間）が過ぎたときに、その部屋のアセットをすべてR2から消します。
データセンターのキャッシュ（Cache API）の写しは、部屋を消したあとも最長7日残ります。
ただし、キャッシュから返すときも先にその部屋のアセットのトークンを確かめ、部屋が消えれば新しいトークンは出ないので、写しを読めるのは消してから最長15分です。

### ログイン

- **PKCE**：ログインから戻ったときのコードは、ログインを始めたAxeが手元に置いた`code_verifier`が無いと、トークンに替えられません。コードを横取りされても使えません。
- **戻り先**：ログインのあとに戻るのは、`ACCESS_CONTROL_ALLOW_ORIGIN`に名前で書いたOriginのページだけです。`*`は数えません。
- **Discordからは最小限**：求めるのは`identify`だけです。Discordのアクセストークンは、その人の情報を1度読んだら捨てます。
- **トークン**：アクセストークンは15分で切れます。リフレッシュトークンは使うたびに替わり、使ったものがまた来たら、その系統をすべて無効にします。同じものが同時に2回来ても通るのは1回だけで、2回目で系統ごと無効にします。どれも、そのものではなくハッシュを置きます。
- **消したアカウント**：`GET`と`DELETE /v1/account`は、トークンのユーザーIDがいまのアカウントと同じときだけ答えます（違えば`404`）。消したあと同じDiscordで作り直したアカウントを、前のアカウントの残ったトークンで見たり消したりはできません。
- **ログインを外したWorker**：あとからログインの3つを外すと、残っている部屋もトークンを一切受けず、見学としてだけ入れます。招待も部屋のアセットのトークンも作りません。
- **cookieを使わない**：トークンはAxeが手元に置き、`Authorization`ヘッダーかWebSocketの最初のメッセージで送ります。

### 役割

- 役割（GM・PL・見学）はサーバーが決めて覚えます。`PeerCursor`の役割を書き換えても、サーバーが戻します。
- `PeerCursor`は、その席だけが書けて消せます。ピアID・ユーザーID・役割は、サーバーが席の値にして置きます。
- ログインしていない人は見学です。見学者が書けるのは、自分のカーソルと、見学者も話せるタブへの発言だけです（→ [部屋のプロトコル](/cloudflare/protocol#見学者が書けるもの)）。
- 役割を変えられるのはGMだけで、部屋のGMがいなくなる変更は断ります。
- 招待はサーバーが署名し、ほかの部屋では使えません。
- 見学者は、ログインした人のユーザーID（`acct_`で始まるもの）と、この部屋にログインして入ったことのあるユーザーIDを名乗れません。見え方はユーザーIDで決まるので、カーソルに見えるユーザーIDを名乗れば、その人の手札や秘話が見えてしまうためです。

### 見えない情報

裏向きのカードの表、他人宛ての秘話、シークレットダイスの結果などは、見てはいけない人の接続にはそもそも送りません。
Axeを改造したり、ブラウザの開発者ツールで通信をのぞいたりしても、届いていないものは見えません。
見えないものに書き込もうとしても断り、伏せた形で持っているものを書き戻しても、本物は上書きされません。
GMでない人は、データ要素の名前を変えたり、ものを別の親の下に移したりして、自分に見えるものを増やすこともできません。
親がまだ届いていないものは、見え方を決められないので、親が届くまでだれにも配りません。

### 部屋のサーバー

- **Origin**：部屋を作る・一覧・入るのどれも、`ACCESS_CONTROL_ALLOW_ORIGIN`に書いたOriginのページからしか受けません。ブラウザはWebSocketにつなぐときもOriginを付けるので、ほかのサイトに置かれたAxeからは使えません。
- **パスワード**：部屋のパスワードは、そのまま置かずにPBKDF2（SHA-256、10万回）のハッシュにして、部屋のDurable Objectにだけ置きます。照らすときは、どこで違っても同じ時間で比べます。間違えると接続を切ります。
- **なりすまし**：イベントの送り主（`sendFrom`）は、サーバーが受けた接続のピアIDで上書きします。サーバー自身のピアID（`@authority`）を名乗ることもできません。サーバーだけが送るイベント（`AUTHORITATIVE_OBJECT`など）は、クライアントが送ってきてもだれにも届けません。ログインした人のピアIDを見学が先に取っていたら、その人が入ってきたときに見学のほうを外します。
- **URLに秘密を載せない**：パスワードはURLではなく、つないだあとの最初のメッセージで送ります。サーバーのログやブラウザの履歴に残りません。
- **量の制限**：部屋を作る・削除する・入るのは送信元ごとに1分30回まで、1つの接続から送れるのは10秒に2000フレームまで、1つの部屋に入れるのは32人までです。gzipを展開して32MiBを超えるものは読まずに切ります。
- **消える**：最後の1人が抜けて24時間（変えられる）で、卓の状態はすべて消えます。部屋の画像と音声も一緒に消えます。

## 守っていないこと

### 置ける人を身内に限るものではない

部屋のアセットは、`ACCESS_CONTROL_ALLOW_ORIGIN`に書いたOriginのページからだけ受けます。
ただし、`Origin`ヘッダーはブラウザ以外（`curl`など）からなら好きな値を付けられます。
これは、ほかのサイトに置かれたAxeからあなたのWorkerが使われるのを防ぐためのもので、置ける人を限るものではありません。

置けるのは、その部屋のGMとPLです。
ただし、Discordのアカウントは誰でも作れ、ログインすれば誰でも部屋を作ってGMになれます。
ログインは「誰が置いたかわかる」ためのもので、置ける人を身内に限るものではありません。
新しく置くPUTは、送信元ごとに1分100件まで（IPv6は/64ごと）に抑えています。

### 部屋の鍵を知っていれば入れる

部屋の一覧は、許可したOriginのページなら誰でも見られ、そこには部屋の鍵も載っています。
パスワードの無い部屋には、一覧から誰でも入れます。SkyWay版のロビーと同じです。
ログインしていれば、ほかの人はPLとして入れます。

- メンバーだけで遊ぶときは、パスワードを付けてください。
- 裏向きのカードの表や他人宛ての秘話は、見てはいけない人には届けません（→ [見えない情報](/cloudflare/rooms#見えない情報)）。ただし、[わざと隠さないもの](/cloudflare/rooms#わざと隠さないもの)は全員に届きます。GMにだけ見せるエフェクトの中身や、隠した罠の場所と中身は、改造したAxeなら読めます。
- 部屋に入れた人は、見学でも、その部屋の画像と音声を読めます。
- 見学者の`userId`は、確かめるすべがありません。見学者宛ての秘話は、その見学者の`userId`を名乗った別の見学者にも届きます。見学者に秘密を伝えるときは、ログインしてもらってください。

### 卓の状態はサーバーに残る

部屋のサーバーは、卓の状態（コマ、カード、チャットなど）をCloudflareのDurable Objectに置きます。
最後の1人が抜けてから24時間は残り、そのあと消えます。
部屋の画像と音声も、部屋が消えるまでR2に残ります。
Workerを置いた人（運営者）は、その間、中身を読み出せる立場にあります。

### Workerを呼ぶ回数そのもの

Workerの中のレート制限は、Workerが呼ばれたあとに働きます。
呼ばれた回数そのものは、Workerの中では減らせません。
読み出しを繰り返されるのが心配なときは、カスタムドメインのゾーンに、Cloudflareの**WAFのレート制限ルール**を足してください。
WAFはWorkerより手前で働くので、Workerが呼ばれる前に止められます。
