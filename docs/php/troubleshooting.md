# PHP版で困ったとき

よくあるつまずきと、確かめる順番をまとめました。
まずブラウザで`/v1/status`を開き、何が返るかを見てください。

## `/v1/status`の結果から探す

| 表示されたもの                              | よくある原因                                      | 見るところ                                 |
| ------------------------------------------- | ------------------------------------------------- | ------------------------------------------ |
| `OK`                                        | 正しく動いている                                  | Axe側の設定（下の「Axeからつながらない」） |
| 真っ白、または「500 Internal Server Error」 | `.env`が無い・読めない・必須の値がない、PHPが古い | [500になる](#_500になる)                   |
| 「404 Not Found」（サーバーの画面）         | `.htaccess`が効いていない、置き場所が違う         | [404になる](#_404になる)                   |
| ファイルの一覧や`index.php`の中身           | PHPが動いていない、`.htaccess`が効いていない      | [404になる](#_404になる)                   |
| `{"error":"Not Found."}`                    | URLの綴りが違う                                   | URLを見直す                                |

## 500になる

1. **`.env`があるか。** FTPクライアントで「隠しファイルを表示する」をオンにして、`index.php`と同じフォルダに`.env`があるかを確かめます。
2. **名前が正しいか。** `.env.txt`や`env`になっていないかを見ます。
3. **必須の値があるか。** `SKYWAY_APP_ID`と`SKYWAY_SECRET`が空でないかを確かめます。
4. **`SKYWAY_UDONARIUM_LOBBY_SIZE`が1以上の整数か。** `3`のように数字だけを書きます。
5. **PHPの版が8.3以上か。** 管理画面でPHPの版を確かめます。8.2以前ではエラーになります。
6. **エラーログ。** レンタルサーバーの管理画面から、PHPのエラーログを見ます。`No .env file found`や`SKYWAY_APP_ID is required`のように、原因が書いてあります。

## 404になる

1. **`.htaccess`が上がっているか。** 隠しファイルを表示して確かめます。
2. **`.htaccess`が効くサーバーか。** `mod_rewrite`と、`.htaccess`での設定変更（`AllowOverride`）が許されている必要があります。サーバーの説明書で確かめてください。
3. **置き場所。** `index.php`が、開いているURLのフォルダの直下にあるかを確かめます。フォルダごとアップロードして、1段深くなっていることがよくあります。

::: warning `.htaccess`が使えないサーバーでは使わないでください
`.htaccess`が効かないと、`.env`がWebから読めてしまうおそれがあります。
その場合は、PHP版ではなく[Vercel版](/vercel/)を使ってください。
:::

## Axeからつながらない

`/v1/status`は`OK`なのに、Axeで部屋に入れないときです。
Axeを開いたブラウザで開発者ツール（F12）を開き、「コンソール」と「ネットワーク」を見ます。

| 見えるもの                                                | 原因と直しかた                                                                                              |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| CORSのエラー（`Access-Control-Allow-Origin`が無い、違う） | `.env`の`ACCESS_CONTROL_ALLOW_ORIGIN`が、Axeを開いているページのOriginと一致していない。末尾の`/`も確かめる |
| `403`と`{"error":"Forbidden."}`                           | 上と同じ。許可していないOriginから来ている                                                                  |
| `400`と`{"error":"Origin is required."}`                  | ブラウザ以外から呼んでいる。`curl`で試すときは`-H "Origin: ..."`を付ける                                    |
| 混在コンテンツ（Mixed Content）のエラー                   | Axeが`https://`なのに、`backend.url`が`http://`になっている                                                 |
| リクエストが飛んでいない                                  | Axeの`assets/config.json`の`backend.url`が空か、間違っている                                                |

## トークンは返るのにSkyWayにつながらない

- **アプリIDとシークレットキーの組み合わせ。** 別のアプリのシークレットキーを書いていると、署名が合わずにSkyWayが断ります。SkyWayのコンソールで、同じアプリのIDとキーかを確かめます。
- **シークレットキーの`#`。** 値を`"`で囲まずに書くと、`#`から後ろが切り捨てられます。`.env`で`"`で囲みます。
- **サーバーの時計。** トークンには発行時刻と期限が入っています。サーバーの時計が大きくずれていると、SkyWayが期限切れと判断することがあります。

## それでも解決しないとき

[Issues](https://github.com/Xelltis/udonarium_axe_backend/issues)で知らせてください。
そのときは、使っているレンタルサーバーの名前、PHPの版、`/v1/status`の結果、開発者ツールに出たエラーを書いてもらえると助かります。
`.env`の中身（特にシークレットキー）は貼らないでください。
