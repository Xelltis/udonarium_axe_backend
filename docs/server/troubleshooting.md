# サーバー版で困ったとき

部屋のサーバー（Cloudflare版とVercel版）で、よくあるつまずきと、その直しかたをまとめました。
上から順に、症状に合うところを探してください。
部屋のサーバーのエラーは`{"error":"<コード>"}`の形で返るので、コードが分かれば、いちばん下の表でも引けます。

## まず確かめること

ブラウザで、部屋のサーバーのURLの後ろに`/v1/login/discord`を付けたものを開きます（例：`https://backend.example.com/v1/login/discord`）。

| 出たもの                        | 意味と、見るところ                                                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `{"error":"invalid-request"}`   | 部屋のサーバーは正しく動いています。[ログインできない](#ログインできない)か、[部屋に入れない・切れる](#部屋に入れない・切れる)へ |
| `{"error":"login-unavailable"}` | ログインの3つが入っていません（→ [設定項目](/server/configuration#ログインの3つ)）                                               |
| `{"error":"config-invalid"}`    | 設定が足りないか、形が違います。下の[設定が読めない](#設定が読めない)へ                                                          |
| エラーの画面、何も出ない        | デプロイが済んでいないか、URLが違います。下の[デプロイでつまずく](#デプロイでつまずく)へ                                         |

## デプロイでつまずく

### Cloudflare版

Workerの画面の**Deployments**から**View build history**を開き、失敗したビルドのログを見ます。

| 見えるもの                                            | 原因と直しかた                                                                                                                                 |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `Please enable R2 through the Cloudflare Dashboard`   | アカウントでR2を使い始めていない（→ [Cloudflareに置く](/server/cloudflare#_2-r2を使い始める-アカウントに一度だけ)）                            |
| バケットを作れない、同じ名前のバケットがある          | 前に同じ名前のWorkerを消したあとなどで、「<Workerの名前>-assets」が残っている。いらなければ消すか、Workerの名前を変える                        |
| Deployボタンの**Create and deploy**を押しても進まない | GitHubに入れた**Cloudflare Workers and Pages**のアプリに、リポジトリを作る権限が無い。GitHubの**Settings**の**Applications**でアプリを入れ直す |
| リポジトリを作れない                                  | 複製先のGitHubのアカウントに、同じ名前のリポジトリがすでにある。リポジトリの名前を変える                                                       |
| `Authentication error`                                | CIからデプロイしていて、APIトークンの権限が足りない（→ [自分のリポジトリから自動でデプロイする](/operate/auto-deploy#apiトークン)）            |

初めてデプロイした直後に、WorkerのURLを開くとエラーの画面が出ることがあります。
1分ほど待ってから、開き直してください。

### Vercel版

| 見えるもの                          | 原因と直しかた                                                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ビルドが失敗する                    | ビルドのログの最後の数行を見る。環境変数の誤りは、ビルドでは見つからない（デプロイしたあとで`config-invalid`になる）                                        |
| 部屋に入れず、WebSocketがすぐ閉じる | プロジェクトでFluid computeが切れている（2025年4月より前に作ったプロジェクト）。**Settings**の**Functions**で有効にするか、`vercel.json`の`fluid`を確かめる |

## 設定が読めない

`config-invalid`が返るときは、足りない設定の名前がログに出ています。

- **Cloudflare版**：Workerの画面の**Logs**（または**Observability**）を開きます。
- **Vercel版**：プロジェクトの**Logs**を開きます。無料のプランでは1時間しか残らないので、URLを開いた直後に見てください。

よくある原因は、次のとおりです。

- ログインの3つのうち、一部だけが入っている。`SESSION_SECRET`が32文字より短い。
- `ACCESS_CONTROL_ALLOW_ORIGIN`が無い。`ROOM_RETENTION_HOURS`が1以上の整数でない（Cloudflare版で`wrangler.jsonc`から消したときも）。
  `ACCESS_CONTROL_ALLOW_ORIGIN`の形が違う（`https://`が抜けているなど）ときは、ここではなく、Axeからの要求が`403 origin-not-allowed`で断られます。
- Vercel版で、RedisかBlobのストアがつながっていない（`REDIS_URL`か`KV_URL`、`BLOB_STORE_ID`が無い）。

直したあとは、Cloudflare版はシークレットの画面で**Deploy**を、Vercel版は**Redeploy**を押します（→ [設定項目](/server/configuration)）。

## ログインできない

| 見えるもの                                         | 原因と直しかた                                                                                                                                                                                                                    |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Discordの画面に`Invalid OAuth2 redirect_uri`と出る | Discordのアプリの**Redirects**に、`https://<部屋のサーバーのドメイン>/v1/login/discord/callback`が入っていない。ドメインは、Axeの`backend.url`と同じにする（→ [Discordのアプリを作る](/server/discord#_3-戻り先のurlを登録する)） |
| Axeに戻ってきたが`login_error=provider-failed`     | `DISCORD_CLIENT_ID`か`DISCORD_CLIENT_SECRET`が、Discordのアプリと合っていない。Client Secretを作り直したときは、サーバーの値も入れ替える                                                                                          |
| ログインを始めると`400 invalid-request`            | Axeを開いているページのOriginが、`ACCESS_CONTROL_ALLOW_ORIGIN`に名前で書かれていない（`*`は数えない）                                                                                                                             |
| ログインの途中の画面で止まる                       | ログインを始めてから10分のうちにDiscordから戻らなかった（Discordのアカウントを作っていた、など）。Axeからログインをやり直す                                                                                                       |

`*.workers.dev`で登録したままカスタムドメインから使うときや、Vercel版でプレビューのURL（`*-git-*.vercel.app`など）から使うときも、`Invalid OAuth2 redirect_uri`になります。

## 部屋に入れない・切れる

部屋のサーバーは、接続を閉じる前に理由を送ります。
Axeの画面や、開発者ツールの**コンソール**に出た理由を、次の表で探します。

| 理由                | 意味と直しかた                                                                                                                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| つないですぐ`403`   | Axeを開いているページのOriginが、`ACCESS_CONTROL_ALLOW_ORIGIN`にない。前は通っていたのに急に出るようになったら、Cloudflare版では`wrangler.jsonc`の値に戻っている（→ [Cloudflareに置く](/server/cloudflare#_8-originの設定を確かめる)） |
| `protocol-mismatch` | Axeと部屋のサーバーの版が合わない。Axeを読み込み直す。それでも直らなければ、部屋のサーバーが古いので、新しい版をデプロイする                                                                                                           |
| `wrong-password`    | パスワードが違う。部屋を作った人に確かめる                                                                                                                                                                                             |
| `room-full`         | 部屋に32人いる。誰かが抜けるのを待つ                                                                                                                                                                                                   |
| `replaced`          | 同じ人が別のタブや端末から入り直したので、古い方を閉じた                                                                                                                                                                               |
| `room-deleted`      | 部屋のGMが部屋を削除した。入るなら作り直す                                                                                                                                                                                             |
| `unauthorized`      | アクセストークンが切れたか、無効。Axeがトークンを替えてつなぎ直す。繰り返すなら、ログインし直す                                                                                                                                        |
| `bad-message`       | 送ったものが読めなかったか、ほかの人のピアIDを名乗った                                                                                                                                                                                 |
| `too-many-messages` | 短いあいだに送りすぎた。ふつうに遊んでいて起きるなら、[Issues](https://github.com/Xelltis/udonarium_axe_backend/issues)で知らせてください                                                                                              |

見学で入っていた人は、同じユーザーIDやピアIDでログインした本人が入ってきたときにも、`unauthorized`や`bad-message`で外れます。
ログインしてから入り直してください。

Vercel版では、数分ごとに部屋のサーバーが接続を閉じて、Axeが静かにつなぎ直します。
ほかの人には何も見えないのがふつうです。
数分ごとに「再接続中」が出るときは、`ROOM_SOCKET_SECONDS`を`maxDuration`より長くしていないかを確かめます（→ [設定項目](/server/configuration#room-socket-seconds)）。

## 画像が部屋のアセットに上がらない

画像を足した人のブラウザで、開発者ツールの**ネットワーク**を開き（→ [設置の準備](/guide/prepare#開発者ツールを開く)）、`/v1/rooms/<部屋の鍵>/assets/`へのリクエストを見ます。

1. **リクエストが飛んでいない**：部屋に入っていません。Axeは、部屋の外（ロビーで待っているあいだ）では何も上げません。
2. **`HEAD`のあとに`PUT`が無い**：`HEAD`が`200`なら、その部屋にすでに置かれています。正常です。
3. **`PUT`が`403 not-a-player`**：見学の席からは置けません。置けるのはGMとPLだけです。
4. **`403 origin-not-allowed`**：`ACCESS_CONTROL_ALLOW_ORIGIN`が、Axeを開いているページのOriginと一致していません。
5. **`401 asset-token-required`**：部屋のアセットのトークンが切れたか、ほかの部屋のものです。部屋に入り直してください。
6. **`PUT`が`415`や`413`**：受け付けない形式か大きさです。その画像は、部屋のサーバーの中継で配られます。
7. **`PUT`が`404 room-not-found`**：部屋が削除されたか、保持期間を過ぎて消えています。
8. **Vercel版で、大きい音声が置かれない**：4,000,000バイトを超えるものは、Blobへ直接上げます。Blobへの`PUT`が断られていないかを見ます。断られていれば、部屋のサーバーの中継で配られます。

## 画像が部屋のアセットから届かない

ほかの参加者のブラウザで、開発者ツールの**ネットワーク**を見ます。

- **`GET`が`404`**：その部屋にまだ置かれていません。部屋のサーバーの中継で届くので、遊ぶのに困ることはありません。
- **`GET`が`429`**：送信元からの読み出しが上限を超えています。同じ回線から大勢が参加している（学校や会社のネットワーク、モバイル回線の共有など）と起きやすくなります。Cloudflare版では、`READ_LIMITER`の上限を上げられます（→ [設定項目](/server/configuration#レート制限を変える)）。
- **混在コンテンツ（Mixed Content）のエラー**：Axeが`https://`なのに、`backend.url`が`http://`になっています。

## 部屋が消えない

時間を過ぎた部屋は、消える前から一覧に出ず、入ることもできません。
中身を消す時刻は、置き場所によって違います。

- **Cloudflare版**：部屋ごとのアラームで、時間になると消します。
- **Vercel版**：部屋の一覧を取る・部屋を作る・部屋に入るのついでと、1日1回のVercel Cronで消します。そのため、消えるのが1日ほど遅れることがあります。

## 費用が気になる・遅い

- **Cloudflare版を`*.workers.dev`のまま使っている**：画像と音声のキャッシュが効かないので、毎回R2から読みます。カスタムドメインを付けてください（→ [Cloudflareに置く](/server/cloudflare#_12-カスタムドメインを付ける)）。
- **リクエストが多すぎる**：どこから多く来ているかを、ダッシュボードで見ます（→ [運用](/operate/#見ておくところ)）。Cloudflare版で読み出しを繰り返されているなら、カスタムドメインのゾーンにWAFのレート制限ルールを足します（→ [安全のしくみ](/operate/security#サーバーを呼ぶ回数そのもの)）。

## エラーのコード

| コード                 | 起きるとき                                                                               | すること                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `config-invalid`       | 設定が足りないか、形が違う                                                               | [設定が読めない](#設定が読めない)                        |
| `login-unavailable`    | ログインの3つが入っていない                                                              | [設定項目](/server/configuration#ログインの3つ)          |
| `origin-not-allowed`   | Originが`ACCESS_CONTROL_ALLOW_ORIGIN`にない                                              | Axeを開いているページのOriginを書く                      |
| `invalid-request`      | 本文の形が違う。部屋の名前が空か長すぎる。ログインの戻り先が許されていない               | 名前は1〜255文字、パスワードは64文字まで                 |
| `login-required`       | 部屋を作る・削除する、アカウントを見る・消すのに、ログインしていない（トークンが切れた） | ログインし直す                                           |
| `invalid-grant`        | ログインのコードやリフレッシュトークンが、無効・使用済み・期限切れ                       | ログインし直す                                           |
| `asset-token-required` | 部屋のアセットのトークンが無い・切れた・ほかの部屋のもの                                 | 部屋に入り直す                                           |
| `not-a-player`         | 見学の席から画像や音声を置こうとした                                                     | 正常な動き。置けるのはGMとPLだけ                         |
| `not-game-master`      | 部屋を削除しようとしたが、その部屋のGMでない                                             | 正常な動き。削除はその部屋のGMに頼む                     |
| `not-found`            | その部屋に置かれていない（部屋と一緒に消えたときも）。アカウントがもう無い               | 正常な動き。画像は部屋のサーバーの中継で届く             |
| `room-not-found`       | その部屋が無い。作られていないか、消えた                                                 | 部屋を作り直す                                           |
| `unsupported-type`     | 受け付けない形式（動画など）                                                             | 正常な動き。その画像は部屋のサーバーの中継で配られる     |
| `too-large`            | 画像が2MiB、音声が10MiBを超えた                                                          | 正常な動き。その画像は部屋のサーバーの中継で配られる     |
| `hash-mismatch`        | 本文のハッシュが名前と合わない                                                           | 正常な動き。その画像は部屋のサーバーの中継だけで配られる |
| `rate-limited`         | 送信元からの上限を超えた                                                                 | 少し待てば戻る。Axeは間を置いて試し直す                  |
| `blocked`              | 運営する人が、その画像を置かせないようにした                                             | 正常な動き。その画像は使わない                           |
| `upgrade-required`     | 部屋に入るURLを、WebSocketでなく普通のリクエストで開いた                                 | 正常な動き。部屋にはAxeからつなぐ                        |

ほかのコードも含めた一覧は、[部屋のサーバーのAPI](/reference/server-api#エラー)にあります。

## それでも解決しないとき

[Issues](https://github.com/Xelltis/udonarium_axe_backend/issues)で知らせてください。
エラーのコード、開発者ツールに出たエラー、ログに出たエラーを書いてもらえると助かります。
設定の値（特にClient Secretと`SESSION_SECRET`）は貼らないでください。
