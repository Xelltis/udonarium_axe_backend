# はじめに

このページでは、Udonarium Axeがどんなサーバーを必要とするのか、このリポジトリに何が入っているのかを説明します。
設置の手順に入る前に、全体の形をつかんでおくと迷わずに済みます。

## Axeは静的なWebアプリ

Udonarium Axe（以下Axe）は、HTMLとJavaScriptだけでできた**静的なWebアプリ**です。
S3やGitHub Pages、レンタルサーバーの公開フォルダなど、ファイルを置ける場所ならどこでも配信できます。

ただし、参加者どうしをつなぐには、Axeの外に何かが要ります。
それを何にするかで、配信の方式が2つに分かれます。

## 2つの方式

### SkyWay版（いまの方式）

参加者どうしのやりとり（コマの移動、チャット、ダイスなど）を、ブラウザ同士の直接通信（P2P）で行います。
直接通信には、NTTコミュニケーションズの[SkyWay](https://skyway.ntt.com/)を使います。

SkyWayにつなぐには、**認証トークン**（JWT）が要ります。
トークンは、SkyWayのアプリごとに発行される**シークレット**（秘密鍵）で署名して作ります。
シークレットをAxeのファイルに埋め込むと誰でも読めてしまうので、トークンは別のサーバーで作り、Axeはそれを受け取るだけにしています。
この「トークンを作って渡すだけのサーバー」が、このリポジトリのPHP版とVercel版です。

SkyWay版では、部屋に置いた画像や鳴らした音声も、ふつうはP2Pで配ります。
参加者が多い卓や、画像の多い部屋では、全員に行き渡るまで時間がかかります。
そこで、画像と音声をHTTPで1か所から配れる**アセットサーバー**を足せるようにしました。
これが、いまのCloudflare版です。

### サーバー版（開発中）

部屋ごとにCloudflareの**Durable Objects**（部屋の状態を持つ小さなサーバー）を置き、参加者はそこにWebSocketでつながります。
SkyWayを使わないので、SkyWayのアプリもトークン発行サーバーも要りません。

サーバー版では、次のこともできるようになります。

- 全員が抜けても、しばらくのあいだ卓が残る
- 裏向きのカードや秘話を、見てはいけない人の画面に届けない
- GMとPLはログインして入り、匿名の人は見学だけにする

部屋のサーバーは、Cloudflare版のWorkerに入っています（→ [部屋のサーバー](/cloudflare/rooms)）。
Axe v1.68.0から、ベータとして使えます（→ [Axe側の設定](/guide/client-config#サーバー版で配信するとき)）。
進み具合は[今後の計画](/guide/roadmap)にあります。

どちらの方式で配信するかは、配信ごとに選びます。
SkyWay版は、サーバー版ができたあとも残ります。

## SkyWay版の全体の形

```text
参加者のブラウザ（Axe）
 ├─ ① トークンをもらう ─────────→ トークン発行サーバー（PHP版 または Vercel版）
 ├─ ② 画像・音声を置く／受け取る ─→ アセットサーバー（Cloudflare版。なくてもよい）
 └─ ③ 参加者どうしで直接やりとり ─→ SkyWay
```

1. 部屋に入るとき、Axeはトークン発行サーバーにトークンを頼みます。
2. 画像や音声を足したり、部屋を読み込んだりすると、Axeはアセットサーバーにそれを置きます。ほかの参加者は、持っていないものをアセットサーバーから受け取ります。
3. 受け取ったトークンでSkyWayにつながり、参加者どうしが直接やりとりします。

## このリポジトリに入っているもの

| ディレクトリ      | 中身                                                                       | 動かす場所                              |
| ----------------- | -------------------------------------------------------------------------- | --------------------------------------- |
| `apps/php`        | SkyWay版のトークン発行サーバー（PHP）                                      | レンタルサーバー（Apache＋PHP 8.3〜）   |
| `apps/vercel`     | 同じトークン発行をTypeScript（Hono）で書いたもの                           | Vercel Functions（Node.js 24）          |
| `apps/cloudflare` | サーバー版のWorker。画像と音声の置き場（アセットサーバー）と部屋のサーバー | Cloudflare Workers＋R2＋Durable Objects |
| `docs`            | このドキュメント（VitePress）                                              | GitHub Pages                            |

SkyWay版で遊ぶなら、PHP版とVercel版のどちらか1つあれば足ります。
Cloudflare版は、それらとは別に、必要なときに足すものです。

## 用語

このドキュメントで使う言葉をまとめておきます。

| 用語               | 意味                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| Origin（オリジン） | Webページの出どころ。`https://axe.example.com`のように、スキーム・ホスト名・ポートの組で、パスは含まない |
| CORS               | ほかのOriginのページからのリクエストを受けるかどうかを、サーバーがブラウザに伝えるしくみ                 |
| JWT                | 署名付きの小さなデータ。SkyWayのトークンはJWTの形をしている                                              |
| SkyWay             | SkyWay版が使うWebRTC（P2P通信）のサービス。アプリごとに「アプリID」と「シークレットキー」が発行される    |
| Worker             | Cloudflareの上で動く小さなプログラム。Cloudflare版はWorker                                               |
| R2                 | Cloudflareのファイル置き場（オブジェクトストレージ）。取り出すときの転送料がかからない                   |
| Durable Objects    | Cloudflareの、状態を持てるWorker。サーバー版では部屋ごとに1つ置く                                        |
