# よくある質問

バックエンド全体に関わる質問をまとめました。
それぞれのアプリに固有の困りごとは、各アプリの「困ったとき」を見てください。

## 設置について

### バックエンドはいくつ要りますか？

いまのSkyWay版なら、トークン発行サーバー（PHP版かVercel版）が1つあれば遊べます。
Cloudflare版は、SkyWayを使わないサーバー版で使うもので、SkyWay版には要りません。
詳しくは[どれを使うか](/guide/choose)を見てください。

### SkyWayなしで遊べますか？

Axe v1.68.0から、**サーバー版**（ベータ）で遊べます。
Cloudflare版のWorkerを部屋のサーバーとして置き、Axeの`config.json`で`transport`を`"server"`にします。SkyWayのアプリもトークン発行サーバーも要りません。
置きかたは[Cloudflare版](/cloudflare/)と[Axe側の設定](/guide/client-config#サーバー版で配信するとき)にあります。

### 本家のユドナリウムでも使えますか？

トークン発行サーバー（PHP版・Vercel版）は、本家ユドナリウムが呼び出すAPI（`POST /v1/skyway2023/token`）にも対応しているので使えます。
Cloudflare版（部屋のサーバー）は、Axe専用です。本家ユドナリウムからは使われません。

### お金はかかりますか？

ふつうの使いかたなら、無料枠の範囲に収まることがほとんどです。

- **PHP版**：契約中のレンタルサーバーで動かすなら、追加の費用はありません。
- **Vercel版**：Vercelの無料プラン（Hobby）で足ります。Hobbyは個人の非商用の利用が前提です。
- **Cloudflare版**：R2とWorkersの無料枠に収まることが多いです。目安は[運用と料金](/cloudflare/operations)にあります。
- **SkyWay**：SkyWayの料金体系に従います。最新の情報は[SkyWayの公式サイト](https://skyway.ntt.com/)で確かめてください。

### 身内用と公開用で分けられますか？

分けられます。
トークン発行サーバーもCloudflare版も、名前を変えればいくつでも置けます。
Cloudflare版は、同じCloudflareアカウントに複数置いても、R2のバケット、部屋、レート制限はWorkerごとに分かれます。

## Originについて

### `ACCESS_CONTROL_ALLOW_ORIGIN`には何を書けばいいですか？

Axeを配信しているページのOriginです。
ブラウザのアドレスバーに出るURLのうち、`https://`からホスト名（とポート）までを書きます。

| アドレスバーのURL                | 書く値                    |
| -------------------------------- | ------------------------- |
| `https://axe.example.com/`       | `https://axe.example.com` |
| `https://example.com/udonarium/` | `https://example.com`     |
| `http://localhost:4200/`         | `http://localhost:4200`   |

複数あるときはカンマで区切ります（例：`https://axe.example.com,https://www.axe.example.com`）。

### 末尾に`/`を付けてもいいですか？

付けないでください。
サーバーによっては、書いた文字列をそのままブラウザに返すため、`https://axe.example.com/`と書くとブラウザが「Originが違う」と判断して通信を止めます。

### `*`（すべて許可）にしてもいいですか？

試すときだけにしてください。
`*`にすると、ほかのサイトに置かれたAxeからも、あなたのSkyWayアプリのトークンを使えてしまいます。
SkyWayの利用量はあなたの契約に数えられるので、本番では必ず具体的なOriginを書いてください。
Cloudflare版の部屋のサーバーでは、`*`だけにするとログインが通らず、部屋も作れません。AxeのOriginを名前で書いてください。

## 画像と音声について

### SkyWay版で、画像と音声のためのサーバーは要りますか？

要りません。
SkyWay版では、画像と音声は参加者どうしのP2Pだけで配ります。

サーバー版では、部屋に置いた画像と音声を、部屋のサーバーが部屋ごとに預かります。

### 置いた画像は、ほかの人に見られますか？

サーバー版の部屋に置いた画像と音声を読めるのは、その部屋の席（GM・PL・見学）だけです。
読むには部屋のサーバーが席に渡すトークンが要るので、中身のSHA-256や部屋の鍵を知っていても、部屋に入っていない人は読めません。
部屋を抜けた人が読めるのは、持っているトークンが切れるまで（長くて15分）です。

ただし、部屋の一覧はだれにでも部屋の鍵を返します。
パスワードの無い部屋には、招待リンクが無くても、ログインしないまま見学として入れ、その部屋の画像と音声も読めます。
メンバー以外に見せたくない部屋には、パスワードを付けてください。
詳しくは[安全のしくみ](/cloudflare/security)にあります。

### 誰でも画像を上げられてしまいませんか？

上げられるのは、部屋にGMかPLとして入っている人だけです。
GMとPLは、Discordでログインして入ります。
見学の人は、受け取ることはできても、上げることはできません。
このほか、`ACCESS_CONTROL_ALLOW_ORIGIN`に書いたOriginのページからしか受けないことと、送信元ごとの上限で、置かれる量を抑えています。

### 画像はいつまで残りますか？

部屋と一緒に消えます。
GMが部屋を削除したときと、最後の1人が抜けてから`ROOM_RETENTION_HOURS`（既定24時間）が過ぎて部屋が消えるときに、その部屋の画像と音声もすべて消します。
人が入ったり抜けたりしながら部屋が続いているあいだは、消えません。
Cloudflareのデータセンターのキャッシュには、部屋を消したあとも写しが最長7日残ります。
ただし、読むには切れていない部屋のアセットのトークンが要るので、読めるのは部屋を消してから長くて15分です。

保存しておいた部屋のデータを新しい部屋で読み込めば、画像と音声はまたその部屋に上がります。

## そのほか

### 脆弱性を見つけました

公開のIssueには書かず、[GitHub Security Advisory](https://github.com/Xelltis/udonarium_axe_backend/security/advisories/new)から非公開で知らせてください。
5営業日以内に返答します。

### 機能の要望や不具合の報告はどこへ？

[Issues](https://github.com/Xelltis/udonarium_axe_backend/issues)へどうぞ。
Axe本体についての要望は、[Axeのリポジトリ](https://github.com/Xelltis/udonarium_axe/issues)へお願いします。
