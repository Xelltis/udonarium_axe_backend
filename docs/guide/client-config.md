# Axe側の設定

Axeは、起動するときに配信先の`assets/config.json`を読み、どのサーバーにつなぐかを決めます。
このページでは、サーバーに関わる設定項目を説明します。

## config.jsonの置き場所

Axeを配信している場所（`index.html`のあるフォルダ）の中の、`assets/config.json`です。

```text
（Axeの配信先）
 ├─ index.html
 └─ assets/
     └─ config.json   ← これ
```

Axeのリリースのzipには、ひな形の値が入った`assets/config.json`が最初から入っています。
設置先でこのファイルを開き、値を書き換えてください。

## 設定項目

```json
{
  "backend": {
    "url": "https://backend.example.com"
  },
  "assets": {
    "url": "https://assets.example.com"
  }
}
```

| 項目          | 必須 | 内容                                                                       |
| ------------- | :--: | -------------------------------------------------------------------------- |
| `backend.url` |  ✅  | トークン発行サーバー（PHP版・Vercel版など）のURL                           |
| `assets.url`  |      | アセットサーバー（Cloudflare版）のURL。空なら画像と音声はP2Pだけで配ります |

URLの末尾の`/`は、あってもなくても構いません。
トークン発行サーバーをサブディレクトリに置いている場合は、`https://example.com/backend`のようにそのパスまで書きます。

### アセットサーバーを使うとき

`assets.url`を書くと、Axeは次のように動きます。

- 自分が足した画像と音声（ファイルの追加、部屋の読み込み、ダイスの絵の保存）を、アセットサーバーに上げます。上げる前に置かれているかを確かめ、無いものだけを送ります。
- ほかの参加者が持っていて自分が持っていない画像と音声は、まずアセットサーバーから受け取ります。無いときや、届いた中身のハッシュが名前と合わないときは、これまでどおり持っている人にP2Pで頼みます。
- URLで指定した画像、組み込みの素材や効果音など、中身のハッシュを名前にしていないものは上げません。

アセットサーバーに上げ終わるまで、その画像は自分のカタログに載せません。
こうしないと、ほかの参加者が先にカタログを受け取り、結局P2Pで頼んできてしまうためです。

## サーバー側との対応

Axe側の設定と、それぞれのサーバーの設定は、次のように対応しています。

| Axe側                   | サーバー側                                                            |
| ----------------------- | --------------------------------------------------------------------- |
| Axeを配信しているOrigin | トークン発行サーバーとアセットサーバーの`ACCESS_CONTROL_ALLOW_ORIGIN` |
| `backend.url`           | トークン発行サーバーのURL。サーバー版ではCloudflare版のWorkerのURL    |
| `assets.url`            | アセットサーバー（Worker）のURL                                       |

## GitHub Actionsで配信している場合

Axeのリポジトリをフォークして、付属のデプロイ用ワークフロー（`.github/workflows/deploy.yml`）でS3とCloudFrontに配信している場合は、`config.json`を手で書く代わりに、GitHubのEnvironmentのSecretに値を入れます。
ワークフローがビルドのあとに`config.json`を作ります。

| Secret        | 入る先        | 必須 |
| ------------- | ------------- | :--: |
| `BACKEND_URL` | `backend.url` |  ✅  |
| `ASSETS_URL`  | `assets.url`  |      |

## ローカル確認モード

Axeを「ローカル確認モード」で起動したときは、ネットワークを使わないので`config.json`は読まれません。
トークン発行サーバーにもアセットサーバーにもつなぎません。

## サーバー版で配信するとき

Axe v1.68.0から、SkyWayを使わずに[部屋のサーバー](/cloudflare/rooms)で配信できます（ベータ）。
`transport`を`"server"`にし、`backend.url`にCloudflare版のWorkerのURLを書きます。

```json
{
  "transport": "server",
  "backend": {
    "url": "https://<WorkerのURL>"
  }
}
```

| 項目          | 内容                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------- |
| `transport`   | `"server"`で部屋のサーバー、`"skyway"`か書かなければSkyWay版。知らない値はSkyWay版として読む |
| `backend.url` | Cloudflare版のWorkerのURL。部屋とログインとアセットのAPIを、すべてここに送る                 |
| `assets.url`  | 空なら`backend.url`のWorkerに画像と音声を置く。別のアセットサーバーを使うときだけ書く        |

どちらで配信するかは配信ごとに選び、部屋ごとには切り替えません。
SkyWay版は、サーバー版ができたあとも残ります。

サーバー版では、Axeは次のように動きます。

- ロビーの上に「Discordでログイン」が出ます。ログインはポップアップで開き、戻り先は配信先と同じOriginの`assets/login-callback.html`です。ポップアップが開けないときは、Axeのページそのものがログインに移って、同じページに戻ってきます。どちらの戻り先も配信先のOriginにあるので、Workerの`ACCESS_CONTROL_ALLOW_ORIGIN`に、配信先のOriginを名前で書いておきます。
- つながっているあいだも、アクセストークンを替えるたびに部屋のサーバーへ渡します。ログアウトしたりアカウントを消したりすると渡せなくなり、トークンが切れて1分のうちに部屋から外れます。
- アクセストークンとリフレッシュトークンは、ブラウザのlocalStorageに置きます。同じブラウザのタブはログインを分け合い、トークンの更新は1つのタブずつ行います。
- 画像と音声を上げるときは、`assets.url`が空で`backend.url`のWorkerに置く場合にだけ、アクセストークンを付けます。別のアセットサーバーにはトークンを送りません。
- 部屋を作れるのはログインした人だけです。ログインしていない人は、ほかの人の部屋に見学として入ります。
