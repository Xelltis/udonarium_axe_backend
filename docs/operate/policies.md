# 運営の方針

部屋のサーバー（Cloudflare版かVercel版）を、身内の外にも開いて運営する人向けのページです。
サーバーが何を預かり、いつ消えるのか、権利侵害の申し立てにどう応えるのかをまとめました。
プライバシーポリシーや利用規約を書くときの材料にしてください。

::: warning 法律の助言ではありません
このページは、部屋のサーバーのしくみを説明するものです。
公開して運営するときの法的な判断は、ご自身で、必要なら専門家に確かめてください。
:::

## サーバーが預かるもの

| もの                 | 中身                                                                                       | 置き場所（Cloudflare版）               | 置き場所（Vercel版） | 消えるとき                                                  |
| -------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------- | -------------------- | ----------------------------------------------------------- |
| アカウント           | DiscordのユーザーID、表示名、アバターのURL、サーバーが決めたユーザーID                     | アカウントのDurable Object             | Redis                | 本人がアカウントを消したとき                                |
| リフレッシュトークン | ハッシュだけ（そのものは置かない）                                                         | アカウントのDurable Object             | Redis                | 30日で使えなくなる。ログアウトやアカウントを消したとき      |
| 卓の状態             | コマ、カード、チャットの発言、部屋の名前、パスワードのハッシュ、ユーザーIDごとの役割       | 部屋のDurable Object                   | Redis                | 部屋が消えるとき（既定は最後の1人が抜けて24時間）           |
| 部屋の一覧           | 部屋の名前、表示用のID、パスワードの有無、人数、部屋ごとのGMのユーザーID                   | ロビーのDurable Object                 | Redis                | 部屋が消えるとき                                            |
| 画像と音声           | 部屋に置かれたファイル（名前は部屋の鍵と中身のSHA-256）と、置いたときのファイル名          | R2のバケット                           | Vercel Blobのストア  | 部屋が消えるとき                                            |
| 画像と音声の写し     | 一度配った画像と音声                                                                       | Cloudflareのデータセンターのキャッシュ | （無い）             | 最長7日。部屋を消しても残るが、読めるのは消してから最長15分 |
| 部屋の記録           | 部屋の鍵、ホスト名、部屋で起きたこと（入った・出た・削除したなど）、役割や接続を閉じた理由 | Workers Analytics Engine               | Functionのログ       | 部屋を消しても残る。Cloudflare・Vercelが決めた期間          |
| ログ                 | 部屋のサーバーへのリクエストの記録（送信元のIPアドレスを含む）                             | Cloudflare（`observability`）          | Vercel（Logs）       | Cloudflare・Vercelが決めた期間                              |

部屋が消えるときは、[部屋が消えるとき](/server/#部屋が消えるとき)にあります。
`ROOM_RETENTION_HOURS`を変えたときは、それに合わせて読み替えてください。

- Discordのメールアドレスや、参加しているDiscordのサーバーは求めず、預かりません。
- Discordのアクセストークンは、その人の情報を1度読むのに使うだけで、置きません。
- cookieは使いません。トークンはAxeが手元（ブラウザ）に置きます。
- レート制限のために送信元のIPアドレスを数えますが、それを置いておくことはしません。
- アカウントは、使われなくなっても自動では消えません。本人が消すか、運営する人が消します。

## 本人がアカウントを消すとき

`DELETE /v1/account`で消せます（→ [アカウントを消す](/reference/server-api#アカウントを消す)）。Axeでは、ロビーの上のアカウント欄にある「アカウントを削除」から消せます。
アカウントの情報とすべてのトークンが消えます。
部屋の席の表には、そのユーザーIDだけが残り、部屋が消えるときに一緒に消えます。
その人が部屋で書いた発言には、書いたときの名前とアバターの画像のURLが載っていて、これも部屋が消えるまで残ります。

## 権利侵害の申し立てに応える

置かれた画像や音声について、権利者から申し立てを受けたときの手順です。

1. 申し立てを受ける窓口（メールアドレスやフォーム）を決め、配信しているページに載せます。
2. 対象の画像のSHA-256を確かめます。画像のURL（`/v1/rooms/<部屋の鍵>/assets/<SHA-256>`）に載っています。
3. 同じ画像を置いている部屋を探します。画像は部屋ごとに置くので、同じものがほかの部屋にもあることがあります。置き場所の`rooms/`の下で、名前が`/<SHA-256>`で終わるものを探します。
4. 見つかったものをすべて消し、同じものをまた置かせない印を置きます。印は、`blocked/<SHA-256>`という名前の、中身が空のファイルです。
5. Cloudflare版で、独自ドメインでWorkerを動かしているなら、ダッシュボードの「キャッシュを削除」で、見つかった部屋ごとの画像のURLを消します。Workerは、一度配った画像を各地のキャッシュに置いて、最大7日そこから配ります。消さないと、そのあいだ、その部屋に入っている人には配り続けます。

すでに受け取ったブラウザの手元にあるものは、こちらからは消せません。

Cloudflare版では、R2のバケットに対して、次のように消して印を置きます。
wranglerにはバケットの中を一覧にするコマンドが無いので、手順3で探すときは、R2のS3互換API（ListObjectsV2）などを使います。

```sh
cd apps/cloudflare
# 消す（見つかった部屋の鍵ごとに）
npx wrangler r2 object delete <Workerの名前>-assets/rooms/<部屋の鍵>/<SHA-256> --remote
# また置かせない印（中身は空）
: > empty
npx wrangler r2 object put <Workerの名前>-assets/blocked/<SHA-256> --file empty --remote
```

Vercel版では、同じことをVercel Blobのストアに対して行います。
プロジェクトの**Storage**でストアを開くと、置いてあるファイルを名前で探して消せます。
印のファイルは、`@vercel/blob`の`put`で、`blocked/<SHA-256>`という名前を付けて置きます（`addRandomSuffix`は使わない）。

印を置いたものを誰かがまた上げようとすると、どの部屋でも`451 blocked`で断ります。
印は、部屋が消えても、取りこぼしの掃除でも消えません。
印が断るのは新しく置くことだけで、すでに置かれているものは消しません。
手順3で同じ画像を探すのは、そのためです。
同じ画像でも、1バイトでも違えば名前（SHA-256）が変わるので、別のものとして置けてしまいます。

::: info 部屋の中身
部屋に置かれたチャットの発言などを、運営する人が個別に消す手段は、いまはありません。
最後の1人が抜けてから`ROOM_RETENTION_HOURS`が過ぎると、部屋ごと消えます。
:::

## 情報流通プラットフォーム対処法

2025年4月に、プロバイダ責任制限法が改められ、情報流通プラットフォーム対処法になりました。
削除の申し出への対応期間（原則7日）や、削除の基準の公表などの義務がかかるのは、総務大臣が指定した大規模な事業者（平均の月間の発信者数が1000万人以上など）です（→ [総務省の指定の発表](https://www.soumu.go.jp/menu_news/s-news/01ryutsu02_02000488.html)）。
Axeのサーバーがこの規模になることは考えにくいですが、損害賠償の責任の制限や発信者情報の開示の決まりは、規模にかかわらずかかります。
申し立ての窓口は用意しておいてください。

## プライバシーポリシーに書くこと

次のことを書いておくと、利用する人が判断できます。
下書きは[プライバシーポリシーのひな形](/operate/privacy-template)にあります。

- 預かるもの（上の表）と、使う目的（ログインして部屋に入る、役割を守る、卓を残す、画像と音声を配る）
- ログインに使う外部のサービス（Discord）と、そこから受け取るもの（ID、表示名、アバター）
- 預かったものが消えるとき（上の表）
- アカウントの消しかた
- 預け先（Cloudflare版はCloudflare。Vercel版はVercelと、Redisの提供元（Upstashなど）。卓の状態、画像と音声、部屋の記録、ログがそこに置かれる）
- Axeの画面が外のサービスにつながるところ（YouTubeの埋め込み、Discordのアバターの読み込み、URLで足した画像の読み込み、キャラクターシートの保管サイトからの取り込み）
- 問い合わせと申し立ての窓口

## 利用規約に書くこと

下書きは[利用規約のひな形](/operate/terms-template)にあります。

- 置いてよいもの・いけないもの（他人の権利を侵すもの、法令に反するもの）
- 卓の保持期間と、それを過ぎると消えること。画像と音声は部屋と一緒に消えること（バックアップはしない）
- 申し立てを受けたときに、予告なく消すことがあること
- 運営の都合で止めることがあること
