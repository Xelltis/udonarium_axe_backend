# トークン発行のしくみ

このページでは、SkyWay版の配信でPHP版とVercel版が発行する認証トークンの中身と、安全のために入れている制限を説明します。
サーバー版（開発中）ではSkyWayを使わないので、このトークンは要りません。
設置するだけなら読まなくても構いませんが、設定項目の意味や、エラーの理由を知りたいときに役立ちます。

## 流れ

1. Axeは部屋に入る前に、トークン発行サーバーへ`POST /v1/skyway2023/token`を送ります。本文には、入りたい部屋のチャンネル名と、自分のピアIDが入っています。
2. サーバーはリクエストを確かめ、SkyWayのシークレットキーで署名したトークン（JWT）を返します。
3. Axeはそのトークンを使ってSkyWayにつながり、ロビーと部屋のチャンネルに入ります。

Axeは最初に`GET /v1/status`でサーバーが動いているかを確かめます。
つながらないときや一時的なエラー（5xx・408・429）のときは、間を置いて何度か試し直します。
起動直後のサーバー（Vercelのコールドスタートなど）で最初の1回が失敗しても、たいていは試し直しで通ります。

## トークンの中身

トークンには、SkyWayに対して「このピアに何を許すか」が書かれています。
PHP版とVercel版は、同じ中身のトークンを作ります。

| 項目       | 値                                                                  |
| ---------- | ------------------------------------------------------------------- |
| 署名方式   | HS256（SkyWayのシークレットキーで署名）                             |
| `jti`      | 発行ごとのランダムなID（UUID v4）                                   |
| `iat`      | 発行した時刻                                                        |
| `exp`      | 有効期限。PHP版は発行から24時間、Vercel版は既定24時間（変えられる） |
| `version`  | `2`                                                                 |
| アプリ     | SkyWayのアプリID。TURNサーバーの利用を許可                          |
| チャンネル | ロビーと、指定された部屋の2種類（下の表）                           |

### チャンネルごとの権限

| チャンネル | 名前                                | 自分（ピアID）にできること                         | ほかのメンバーへの許可 |
| ---------- | ----------------------------------- | -------------------------------------------------- | ---------------------- |
| ロビー     | `udonarium-lobby-*-of-<ロビーの数>` | チャンネルを見る・作る・入る。データは送受信しない | なし                   |
| 部屋       | リクエストの`channelName`           | チャンネルを見る・作る・入る。データを送受信する   | シグナリングだけ       |

- **ロビー**は、部屋の一覧を見るためのチャンネルです。データのやりとりは許していません。
- **部屋**は、実際に遊ぶチャンネルです。自分のピアIDでだけ、データを送ったり受け取ったりできます。

### ロビーの数

ロビーの名前の`*`には、`1`から`<ロビーの数>`までの番号が入ります。
Axeはトークンに書かれた名前からロビーの数を読み取り、1番から順に見て、300人に満たないロビーに入ります。

ロビーの数は、PHP版・Vercel版とも`SKYWAY_UDONARIUM_LOBBY_SIZE`で決めます（既定は`3`）。
同時にロビーにいる人が多い（数百人を超える）ときは増やします。

::: warning 同じSkyWayアプリを複数のサーバーで使うとき
ロビーの数は、同じSkyWayアプリを使うすべてのトークン発行サーバーでそろえてください。
数が違うと、サーバーごとに見えるロビーが変わり、同じ部屋一覧を見られなくなります。
:::

## 安全のための制限

SkyWayは、チャンネル名やメンバー名の`*`を「何にでも一致する」ワイルドカードとして、`\`をその打ち消しとして扱います。
リクエストの値をそのまま使うと、たとえば`channelName`に`*`を渡すだけで、すべての部屋に入れるトークンができてしまいます。

PHP版は、これを防ぐために次のリクエストを`400`で断ります。

- `channelName`または`peerId`が空、または200バイトを超える
- `channelName`または`peerId`に`*`か`\`が含まれる
- `channelName`が`udonarium-lobby-`で始まる（ロビーの名前を部屋として使い、ロビーにデータ送受信の権限を得るのを防ぐため）
- `formatVersion`が`1`でない

## Originの確認（CORS）

トークン発行サーバーは、`ACCESS_CONTROL_ALLOW_ORIGIN`に書いたOriginのページからのリクエストだけを受けます。

- `Origin`ヘッダーがないリクエストは`400`で断ります。
- 許可していないOriginからのリクエストは`403`で断ります。
- ブラウザのプリフライト（`OPTIONS`）にも答えるので、Axeは`Content-Type: application/json`を付けて送れます。

ただし、`Origin`ヘッダーはブラウザ以外（`curl`など）からなら好きな値を付けられます。
Originの確認は、ほかのサイトに置かれたAxeからあなたのサーバーが使われるのを防ぐためのもので、すべての不正な利用を止めるものではありません。
