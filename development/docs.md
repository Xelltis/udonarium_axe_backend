# ドキュメントを書く

このリポジトリの文書は、2つに分かれています。

| 置き場所       | 読む人                                      | 形                                                                                |
| -------------- | ------------------------------------------- | --------------------------------------------------------------------------------- |
| `docs/`        | Axeを配信する人のうち、サーバーを置く人だけ | [VitePress](https://vitepress.dev/)のサイト。`main`に入るとGitHub Pagesに公開する |
| `development/` | このリポジトリの開発に参加する人            | GitHubでそのまま読むMarkdown。サイトには載せない                                  |

公開するサイトは、サーバーを置く人だけが読みます。
開発の決まり、CI、設計、部屋のプロトコル、サーバーとAxeの中の動きのように、置く人に要らないものは`development/`に書きます。

## 手元で見る

```sh
npm install            # リポジトリのルートで
npm run docs:dev       # http://localhost:5173/udonarium_axe_backend/
```

ファイルを保存すると、ブラウザの表示がすぐに変わります。

公開するものと同じ形で確かめるときは、ビルドしてから見ます。

```sh
npm run docs:build     # docs/.vitepress/dist に書き出す
npm run docs:preview
```

ビルドは、存在しないページへのリンクがあると失敗します。
ページの中の見出しへのリンク（`/server/#招待`のような`#…`）は、ビルドでは確かめないので、別に確かめます。

```sh
npm run docs:check     # 見出しへのリンクが、どれもある見出しを指しているか
```

## サイトのファイルの置き場所

| 場所               | 中身                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------- |
| `docs/index.md`    | トップページ                                                                          |
| `docs/guide/`      | はじめに、どれを置くか、設置の準備、Axeの設定、よくある質問                           |
| `docs/skyway/`     | SkyWay版のしくみ、SkyWayのアプリ、置きかた（Vercel・PHP）、設定、困ったとき           |
| `docs/server/`     | サーバー版のしくみ、Discordのアプリ、置きかた（Cloudflare・Vercel）、設定、困ったとき |
| `docs/operate/`    | 運用、費用と上限、安全のしくみ、運営の方針、規約のひな形、自動デプロイ                |
| `docs/reference/`  | トークン発行サーバーと部屋のサーバーのAPIと、エラーのコード                           |
| `docs/.vitepress/` | 設定（`config.mts`）、見出しのidの作りかた（`slugify.mjs`）、テーマ                   |

ページを足したら、`docs/.vitepress/config.mts`の`sidebar`にも足してください。

サイトのページは、サーバーを置く人に向けて書きます。
置く人が何をしたいか（選ぶ、置く、設定する、困ったときに調べる、公開して運営する）でページを分け、手順と、置くのに要る決まりだけを書きます。
参加者のことは、置く人が知っておくこと（参加者から見て変わること、参加者に頼むこと）として書きます。

1つの事実は、1つのページにだけ書き、ほかのページからはリンクします。
たとえば、部屋が消えるときは[サーバー版のしくみ](https://xelltis.github.io/udonarium_axe_backend/server/#部屋が消えるとき)に、エラーのコードの一覧は[部屋のサーバーのAPI](https://xelltis.github.io/udonarium_axe_backend/reference/server-api#エラー)に書きます。
同じことを何ページにも写すと、直すときに写しのどれかが取り残されます。

Cloudflare版とVercel版の両方に当てはまることは、どちらか一方の名前（Worker、R2など）で書かずに、「部屋のサーバー」「置き場所」のように書きます。
違うところだけ、版の名前を付けて書き分けます。

`apps/`の中には、READMEや説明書を置きません。
置く人に向けた説明は`docs/`に、開発の決まりは`development/`に書きます。
Deployボタンで複製したリポジトリと、PHP版のzipにも説明書は入らないので、コードのコメントから説明を指すときは、サイトのURLを書きます。

`development/`のMarkdownから、ほかの`development/`のページへは相対パス（`./protocol.md#…`）で、サイトのページへはサイトのURLでリンクします。
GitHubは、見出しのidをサイトと違う決まりで作ります（`` `POST /v1/rooms` ``なら`post-v1rooms`）。

## 書きかた

まとまった日本語（README、`docs/`と`development/`の本文）は、`yomiyasu`スキルを通して書きます。
フロントエンドと同じ決まりで、プラグインは`.claude/settings.json`の`enabledPlugins`で有効にしてあります。
ほかの日本語校正スキルとは、指示がぶつかるので同時に使いません。
1〜2行の追記や表のセルの手直しは、そのまま書いてかまいません。

- 日本語で、です・ます調で書きます。
- 1文ごとに改行します。段落の中の改行は、表示では詰まります（日本語どうしの間に空白は入りません）。
- 和文と英数字の間に、半角の空白を入れません（例：`Vercel版`、`R2のバケット`、`` `wrangler.jsonc`の ``）。
- 見出しを変えると、その見出しへのリンク（`#…`）が変わります。見出しを変えたら、そのページへのリンクを探して直し、`npm run docs:check`で確かめます。
- 各ページの最初の数行で、何のページか、どんなときに読むページかを書きます。
- 画面に出るボタンの名前は、実際の表示と同じにします。確かめられなかった名前は、言い切らずに、何をするボタンかで書きます。
- 秘密の値（シークレットキーなど）は、例でも本物を書きません。
- Markdownには、Prettierをかけません。関係のない表の幅まで変わるので、表は手でそろえます。

## 公開

`main`に`docs/`の変更が入ると、`.github/workflows/docs.yml`がビルドしてGitHub Pagesに公開します。
Pull Requestでは、CIの`Docs`ジョブが、見出しへのリンクと、ビルドが通るかだけを確かめます。
