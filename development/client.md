# Axeの中の動き（サーバー版）

サーバー版で配信したとき、Axeが部屋のサーバーとどうやりとりするかを説明します。
Axeやサーバーを直したい人、ふるまいの理由を知りたい人に向けたページです。
Axeの`config.json`の書きかたは[Axeの設定](https://xelltis.github.io/udonarium_axe_backend/guide/client-config)にあります。

## ログイン

- ロビーの上に「Discordでログイン」が出ます。ログインはポップアップで開き、戻り先は配信先と同じOriginの`assets/login-callback.html`です。ポップアップが開けないときは、Axeのページそのものがログインに移って、同じページに戻ってきます。
- どちらの戻り先も配信先のOriginにあるので、部屋のサーバーの`ACCESS_CONTROL_ALLOW_ORIGIN`には、配信先のOriginを名前で書いておきます（`*`は戻り先に数えません）。
- アクセストークンとリフレッシュトークンは、ブラウザのlocalStorageに置きます。同じブラウザのタブはログインを分け合い、トークンの更新は1つのタブずつ行います。
- つながっているあいだも、アクセストークンを替えるたびに部屋のサーバーへ渡します。
- ログアウトしたりアカウントを消したりすると、Axeはその場で、同じ部屋に見学として入り直します。
- 部屋を作れるのは、ログインした人だけです。ログインしていない人は、ほかの人の部屋に見学として入ります。

ログインの流れとトークンの種類は、[部屋のサーバーの中の動き](./room-server.md#ログイン)にあります。

## 画像と音声

Axeは、部屋に入っているあいだ、次のように動きます。

- 自分が足した画像と音声（ファイルの追加、部屋の読み込み、ダイスの絵の保存）を、その部屋に上げます。上げる前に置かれているかを確かめ、無いものだけを送ります。
- GMかPLとして部屋に入ったときと、つなぎ直したときは、手元の画像と音声のうち、その部屋にまだ無いものを上げます。部屋の外で足したものや、別の部屋から持ち込んだものがあるためです。
- 部屋のサーバーに頼まれた別の接続へのつなぎ直し（close code `1012`）のときは、切れているあいだに足したものだけを上げます。上げきれなかったものは、部屋ごとに1回だけ、2分後に上げ直します。
- `403 not-a-player`は、GMやPLの席がまだ部屋に入り直していないとき（Vercel版で受け持ちが替わった直後）にも返るので、上げきれなかったものとして上げ直します。それ以外の`400`・`403`・`413`・`415`・`451`は、置けないものとしてあきらめます。
- ほかの参加者が持っていて自分が持っていない画像と音声は、まず部屋のアセットから受け取ります。無いときや、つながらないとき、届いた中身のハッシュが名前と合わないときは、持っている人から部屋のサーバーの中継で受け取ります。
- URLで指定した画像、組み込みの素材や効果音など、中身のハッシュを名前にしていないものは上げません。

自分が部屋に上げる画像と音声は、上げ終わるまで自分のカタログに載せません。
上げている最中のもののほか、順番を待っているもの、失敗してもう一度上げるのを待っているもの、部屋のサーバーにつながらないあいだに足したものも同じです。
こうしないと、ほかの参加者が先にカタログを受け取り、結局持っている人に頼んできてしまうためです。
もう一度上げても届かないままのものは、カタログに載せて、持っている人から受け取ってもらいます。

- 大きい音声を上げているあいだも小さい画像が待たされないように、2MB以下のものは別の枠で上げます。
- Vercel版のように、1回の`PUT`で置ける大きさに上限のある部屋のサーバーでは、それより大きいものを置き場所へ直接上げます（→ [置き場所へ直接上げる](https://xelltis.github.io/udonarium_axe_backend/reference/server-api#置き場所へ直接上げる)）。
- 部屋の外（ロビーで待っているあいだ）は、画像と音声を上げることも受け取ることもしません。

部屋のアセットを読み書きするときは、部屋のサーバーが席に渡すトークンを付けます。
ログインのアクセストークンは使えません。
このトークンは15分で切れるので、Axeは切れる前に、新しいものを部屋のサーバーからもらいます（→ [部屋のアセットのトークン](https://xelltis.github.io/udonarium_axe_backend/reference/server-api#部屋のアセットのトークン)）。

### 部屋から消す

部屋のGMは、参加者が足した画像と音声を、部屋から消せます。
画像パネルでは、チェックした画像を「削除」で消します。ジュークボックスでは、ライブラリの行ごとの削除ボタンで消します。どちらのボタンも、GMにだけ出ます。
消せるのは、中身のSHA-256を名前にしているもの（参加者が足したもの）だけです。組み込みの画像、URLで指定した画像、「システム予約」のタグが付いた画像は消せません。

押すと、消す件数と、部屋の中でそれを使っているところの数を出して、確かめます。使っているところには、タグ、消したことの記録、チャットは数えません。
確かめる画面には、取り消せないことと、同じファイルを足し直せば戻ることも出します。
消したあとは、「N件の画像を削除しました」（音声なら「N件の音声を削除しました」）と知らせます。

消したことは、同期するオブジェクト`asset-removal`として部屋に書きます。
識別子は`asset-removal_<SHA-256>`です。

| 属性              | 内容                                  |
| ----------------- | ------------------------------------- |
| `assetIdentifier` | 消した画像か音声の名前（SHA-256）     |
| `kind`            | `image`か`audio`                      |
| `removed`         | 消しているあいだは`'1'`、戻したら`''` |

戻すときも`destroy`はせず、`removed`を`''`にします。
部屋のサーバーはオブジェクトの種類を区別せずに持つので、あとから入った席にも届きます。
古い版のAxeは、知らないオブジェクトとして読み飛ばします。部屋の保存（zip）には入れません。

- 各席は、`removed`が`'1'`の記録を見て、その画像か音声を手元から捨てます。そのあとは、ほかの参加者のカタログ、部屋のアセットの一覧、ほかの参加者からの送信のどれから来ても取り込まず、受け取りも始めません。
- 記録が無くなれば（別の部屋に移ったときなど）、取り込まないのもやめます。
- コマなどからの参照は書き換えないので、そのコマは絵の無い状態になります。音声を消すときは、部屋で鳴っているBGMや環境音を先に止めます。
- 同じファイルを足し直すと、記録の`removed`を`''`に戻し、部屋に戻ります。画像を足せる人ならだれでもできます。消したあとに、その画像を含む古いzipを読み込んだときも戻ります。

サーバー版では、記録を書いたあと、GMの席が置き場所からも消します（→ [`DELETE /v1/rooms/:roomKey/assets/:sha256`](https://xelltis.github.io/udonarium_axe_backend/reference/server-api#delete-v1-rooms-roomkey-assets-sha256)）。

- `204`と`404`のときは、それ以上何もしません。`404`には、このAPIの無い古い部屋のサーバーが返す`not-found`も含みます。
- `429`のときは、待ってから送り直します。
- `400`と`403`のときは、あきらめます。
- そのほか（`5xx`やつながらないとき）は、少し間をあけて3回まで送り直します。

置き場所に残っても、各席は記録を見て取りに行きません。
Cloudflare版のデータセンターのキャッシュに写しが残っていても、Axeは読みに行かないので、画面には出ません。
新しい版の席は、消したものを手元に持っていないので、部屋に入り直しても上げ直しません。
古い版の席や、記録が届く前に上げ直した席の分は、置き場所に残ることがあります。

## つなぎ直し

- 部屋に入ったあとで接続が切れたときは、同じピアIDで、1、2、4、8、15秒おきにつなぎ直します。
- 部屋のサーバーが「別の接続でつなぎ直して」と言って閉じたとき（close code `1012`、reason `rotate`か`moved`）は、すぐにつなぎ直し、ほかの人には何も見せません。Vercel版では、数分ごとにこれが起きます（→ [別の接続でつなぎ直してもらう](./protocol.md#別の接続でつなぎ直してもらう)）。
- 部屋に入ったあとで、満員（`room-full`）か送りすぎ（`too-many-messages`）で閉じられたときも、同じようにつなぎ直します。放っておかれて`idle`で閉じられたときは、[放っておかれたページ](#放っておかれたページ)のとおりにします。そのほかの理由で断られたときは、エラーを出して部屋を出ます。
- 満員の部屋に入ろうとしたときは、つなぎ直さずに、すぐ断ります。
- つなぎ直しているあいだに送ろうとした物のうち、削除（2万件まで）、消した物を戻す知らせ（`FORGET_DELETED_OBJECTS`）、変更（削除と削除のあいだで、オブジェクトごとに最後の1件）、役割の頼み（64件まで）を取っておき、入り直したら送った順に送ります。そのほかの変更は、入り直したときのカタログの交換で届きます。手動の「再接続」、5回つながらずにあきらめたとき、部屋を出たときは、取っておいた物を捨てます。`hello`のあと45秒たっても`welcome`が来ないときは、切れたものとみなしてつなぎ直します（受け持ちのインスタンスが黙って止まった部屋で、待ち続けないため）。つなぎ直したときの`welcome`に無い人は、15秒待ってから部屋を出たものとします。まだ`DELETE_GAME_OBJECT`を送っていないものが`AUTHORITATIVE_OBJECT`で返ってきたときは、受け取らずに削除を送り、そのあとのサーバーの答えに任せます。サーバーで振るダイスは取っておかず、同じ部屋に入り直したとき（ログインやログアウトで席が変わったときや、あきらめたあとロビーから入ったときも）に、結果の届いていないものを頼み直します。別の部屋に入ったときは捨てます。リプレイの盤面を見ているあいだは頼まずに持ち、盤面から戻ったときに頼み直します。入り直して頼み直したものが`invalid`で断られたときは、5秒後に1度だけ頼み直します。切れているあいだに作ったタブは、入り直したときのカタログの交換でサーバーに届くので、頼み直しの方が先に着くことがあるためです。
- 送った削除が断られて`AUTHORITATIVE_OBJECT`で返ってきたときは、一緒に返ってきたオブジェクトのうち、削除を送ったものとその下にあるもの（返ってきた`parentIdentifier`でたどる）の削除を、まだ送っていなければ捨てます。断られたタブの中の行の削除が、行を守る20秒より後に届いて消してしまわないようにするためです。変更を断られて返ってきただけのものは、削除を捨てません。捨てると、子だけが消えて本体が残るためです。

- 自分が消したものの変更が届いたときは、ピアどうしなら消したことを伝えますが、部屋のサーバーには伝えず、そのものをサーバーに頼み直します。サーバーが配ってきた変更なら、サーバーにはまだそのものがあり、消したことを伝えると全員から消えるためです。サーバーの答えは、それより前に自分が送った削除のあとに来ます。自分が送った変更のこだまでは頼み直しません。頼んだあとは、サーバーの答え（`@authority`からの`UPDATE_GAME_OBJECT`・`AUTHORITATIVE_OBJECT`・`DELETE_GAME_OBJECT`・`WITHDRAW_GAME_OBJECT`）が来るまで、ほかの人の変更が届いても作り直しません。読み込みでその名前が戻ってくると知らされたとき（`FORGET_DELETED_OBJECTS`）と、部屋を開き直したときは、答えを待つのをやめます。

## 放っておかれたページ

部屋のサーバーは、3時間（`IDLE_SECONDS`）のあいだ操作の知らせ（`active`）が届かない席を、`idle`で閉じます（→ [`active`](./protocol.md#active)）。
開いたまま忘れられたタブが、部屋を残し続けたり、Vercel版で費用を使い続けたりしないためです。

- Axeは、ポインタ・キー・ホイール・タッチの操作があった時刻を覚えます。ページを開いた時刻も、操作として数えます。
- つなぐたびに、最後の操作からのミリ秒を`hello`の`idleMs`に入れます。Vercel版で数分ごとにつなぎ直しても、放っておかれた時間は続けて数えられます。
- 部屋のサーバーが最後に操作を知った時刻を覚えます。`active`を送った時刻か、つないだときの`idleMs`が指す最後の操作の時刻です。サーバーが数え始める時刻と同じにするためです。
- その時刻から5分（`ACTIVE_REPORT_SECONDS`）以上たって操作があれば、`active`を送ります。送るのは、部屋に入っているあいだ（`welcome`のあと）だけです。
- その時刻から2時間55分たつと、まもなく部屋から抜けることを知らせます。操作すれば`active`を送り、知らせを消します。
- `idle`で閉じられたときは、つなぎ直さずに、部屋の画面のまま、部屋に戻るかを尋ねます。戻ると答えたら、同じピアIDでつなぎ直します。卓の画面とBGMはそのままです。抜けているあいだに手元でした変更は、つなぎ直すときと同じく取っておき、戻ったら送ります。

## 送る量

部屋のサーバーは、1つの接続から10秒に2000フレームか20000イベントを超えて届くと、その接続を切ります（`too-many-messages`）。そのためAxeは、11秒あたり900フレーム・9000イベントまでに抑えて送ります。上限の半分より少ないので、回線で遅れた分が次の分と同じ10秒に入っても切られません。行の多いタブの削除や大きな部屋の読み込みは、何回かに分けて届きます。

- 送る順は変えません。サーバーあての頼み（ダイス・役割の変更・取り寄せ）も、先に送った物の後ろに並びます。
- 招待やトークンの更新など、接続そのものの知らせは待たせません。
- 送り終わる前に部屋を出ようとしたり再接続しようとしたりすると、確認を出します。
