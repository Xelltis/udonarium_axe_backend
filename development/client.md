# Axeの中の動き（サーバー版）

サーバー版で配信したとき、Axeが部屋のサーバーとどうやりとりするかを説明します。
Axeやサーバーを直したい人、ふるまいの理由を知りたい人に向けたページです。
Axeの`config.json`の書きかたは[Axeの設定](https://xelltis.github.io/udonarium_axe_backend/guide/client-config)にあります。

## ログイン

- ロビーの上に「Discordでログイン」が出ます。ログインはポップアップで開き、戻り先は配信先と同じOriginの`assets/login-callback.html`です。ポップアップが開けないときは、Axeのページそのものがログインに移って、同じページに戻ってきます。
- どちらの戻り先も配信先のOriginにあるので、部屋のサーバーの`ACCESS_CONTROL_ALLOW_ORIGIN`には、配信先のOriginを名前で書いておきます（`*`は戻り先に数えません）。
- アクセストークンとリフレッシュトークンは、ブラウザのlocalStorageに置きます。同じブラウザのタブはログインを分け合い、トークンの更新は1つのタブずつ行います。
- つながっているあいだも、アクセストークンを替えるたびに部屋のサーバーへ渡します。
- ログアウトしたりアカウントを消したりすると、Axeはその場で、同じ部屋に見学として入り直します。
- 部屋を作れるのは、ログインした人だけです。ログインしていない人は、ほかの人の部屋に見学として入ります。

ログインの流れとトークンの種類は、[部屋のサーバーの中の動き](./room-server.md#ログイン)にあります。

## 画像と音声

Axeは、部屋に入っているあいだ、次のように動きます。

- 自分が足した画像と音声（ファイルの追加、部屋の読み込み、ダイスの絵の保存）を、その部屋に上げます。上げる前に置かれているかを確かめ、無いものだけを送ります。
- GMかPLとして部屋に入ったときと、つなぎ直したときは、手元の画像と音声のうち、その部屋にまだ無いものを上げます。部屋の外で足したものや、別の部屋から持ち込んだものがあるためです。
- 部屋のサーバーに頼まれた別の接続へのつなぎ直し（close code `1012`）のときは、切れているあいだに足したものだけを上げます。上げきれなかったものは、部屋ごとに1回だけ、2分後に上げ直します。
- ほかの参加者が持っていて自分が持っていない画像と音声は、まず部屋のアセットから受け取ります。無いときや、つながらないとき、届いた中身のハッシュが名前と合わないときは、持っている人から部屋のサーバーの中継で受け取ります。
- URLで指定した画像、組み込みの素材や効果音など、中身のハッシュを名前にしていないものは上げません。

自分が部屋に上げる画像と音声は、上げ終わるまで自分のカタログに載せません。
上げている最中のもののほか、順番を待っているもの、失敗してもう一度上げるのを待っているもの、部屋のサーバーにつながらないあいだに足したものも同じです。
こうしないと、ほかの参加者が先にカタログを受け取り、結局持っている人に頼んできてしまうためです。
もう一度上げても届かないままのものは、カタログに載せて、持っている人から受け取ってもらいます。

- 大きい音声を上げているあいだも小さい画像が待たされないように、2MB以下のものは別の枠で上げます。
- Vercel版のように、1回の`PUT`で置ける大きさに上限のある部屋のサーバーでは、それより大きいものを置き場所へ直接上げます（→ [置き場所へ直接上げる](https://xelltis.github.io/udonarium_axe_backend/reference/server-api#置き場所へ直接上げる)）。
- 部屋の外（ロビーで待っているあいだ）は、画像と音声を上げることも受け取ることもしません。

部屋のアセットを読み書きするときは、部屋のサーバーが席に渡すトークンを付けます。
ログインのアクセストークンは使えません。
このトークンは15分で切れるので、Axeは切れる前に、新しいものを部屋のサーバーからもらいます（→ [部屋のアセットのトークン](https://xelltis.github.io/udonarium_axe_backend/reference/server-api#部屋のアセットのトークン)）。

## つなぎ直し

- 部屋に入ったあとで接続が切れたときは、同じピアIDで、1、2、4、8、15秒おきにつなぎ直します。
- 部屋のサーバーが「別の接続でつなぎ直して」と言って閉じたとき（close code `1012`、reason `rotate`か`moved`）は、すぐにつなぎ直し、ほかの人には何も見せません。Vercel版では、数分ごとにこれが起きます（→ [別の接続でつなぎ直してもらう](./protocol.md#別の接続でつなぎ直してもらう)）。
- 部屋に入ったあとで、満員（`room-full`）か送りすぎ（`too-many-messages`）で閉じられたときも、同じようにつなぎ直します。そのほかの理由で断られたときは、エラーを出して部屋を出ます。
- 満員の部屋に入ろうとしたときは、つなぎ直さずに、すぐ断ります。
- つなぎ直しているあいだに送ろうとした物のうち、削除（2万件まで）、消した物を戻す知らせ（`FORGET_DELETED_OBJECTS`）、変更（削除と削除のあいだで、オブジェクトごとに最後の1件）、役割の頼み（64件まで）を取っておき、入り直したら送った順に送ります。そのほかの変更は、入り直したときのカタログの交換で届きます。手動の「再接続」、5回つながらずにあきらめたとき、部屋を出たときは、取っておいた物を捨てます。サーバーで振るダイスは取っておかず、入り直したときに、結果の届いていないものを頼み直します。
- 送った削除が断られて`AUTHORITATIVE_OBJECT`で返ってきたときは、一緒に返ってきたオブジェクトのうち、削除を送ったものとその下にあるもの（返ってきた`parentIdentifier`でたどる）の削除を、まだ送っていなければ捨てます。断られたタブの中の行の削除が、行を守る20秒より後に届いて消してしまわないようにするためです。変更を断られて返ってきただけのものは、削除を捨てません。捨てると、子だけが消えて本体が残るためです。

## 送る量

部屋のサーバーは、1つの接続から10秒に2000フレームか20000イベントを超えて届くと、その接続を切ります（`too-many-messages`）。そのためAxeは、11秒あたり900フレーム・9000イベントまでに抑えて送ります。上限の半分より少ないので、回線で遅れた分が次の分と同じ10秒に入っても切られません。行の多いタブの削除や大きな部屋の読み込みは、何回かに分けて届きます。

- 送る順は変えません。サーバーあての頼み（ダイス・役割の変更・取り寄せ）も、先に送った物の後ろに並びます。
- 招待やトークンの更新など、接続そのものの知らせは待たせません。
- 送り終わる前に部屋を出ようとしたり再接続しようとしたりすると、確認を出します。
